# PR Report: Collected return restoration

Related PR: [#4242](https://github.com/6529-Collections/6529seize-frontend/pull/4242)

## Summary

Returning from a Details artwork could focus the right activity row while
leaving it offscreen. Keep that row visible through the brief period in which
Details sizing and browser scroll restoration settle.

## What Changed

- Collected activity returns observe clipping and ancestor resizing for at most
  two seconds, correcting visibility only when needed.
- User input, focus changes, navigation and unmount immediately end restoration;
  the existing history anchor and query preservation remain intact.
- A late Details expansion case preserves the same return-page, focus and
  visibility contract. Collected documentation and the Help Bot corpus describe
  the interaction behavior.

## Risks / Follow-Ups

- Changes after the two-second window are outside this correction. The exact
  event ordering behind every historical production failure remains unproven.
- An existing production failure to render the fifth distribution row before
  artwork navigation remains separate from return restoration.
- Local branch application integration has now been verified through ordinary
  return and delayed Details expansion on desktop and mobile. Production build
  and prefetch timing still require the ordinary deployment path.
- Default Turbopack supports this local flow. The existing Waves stylesheet has
  a separate Webpack purity error; it was left outside this fix.
