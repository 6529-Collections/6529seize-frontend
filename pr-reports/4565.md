# PR Report: Historical Timeline Arweave Fallbacks

PR: https://github.com/6529-Collections/6529seize-frontend/pull/4565
Branch: `agent-prxt/nft-timeline-arweave-fallbacks` -> `main`

## Summary

The Memes and Meme Lab Timeline previews can recover an unavailable recorded
Arweave source through the existing media resolver and approved gateways while
preserving the exact historical transaction ID and file path.
Historical animations also use their recorded before/after formats rather than
the current NFT's format, so a removed video remains a video.

## What Changed

- Keep the recorded media URL first. Try each matching fallback at most once
  for image and video failures, and HTML frame errors or loading timeouts.
- Select each animation preview from its own historical format. When absent or
  unrecognized, inspect the historical source's content type through a bounded
  header-only request, using only matching gateways. Keep an original-media
  link if detection fails instead of assuming an image.
- Reject candidates that resolve to a different transaction or path, including
  case differences. Reset preview state when its recorded URL or media type changes.
- Retain the configured media resolver on alternate hosts or path prefixes when
  its actual request path preserves the complete historical reference.
- Capture non-bubbling HTML frame errors. Ignore stale frame events after a
  source advance; batched errors advance only once. Video retries preserve the
  shared player's ordered, finite source list.
- Preserve HTML sandbox restrictions, accessible preview labels, and existing
  behavior after all candidates fail.
- Update the shared media recovery guide, both collection guides, and Help Bot
  knowledge.

## Scope

The change affects `/the-memes/{id}?focus=timeline` and
`/meme-lab/{id}?focus=timeline` through their shared Timeline media renderer.
The API continues to return stored historical changes. Backend historical
metadata retrieval already supports bounded matching Arweave gateway fallbacks;
no backend, ingestion, replay, contract, or configuration changes are required.

## Release Notes

Historical artwork previews can load from another supported Arweave gateway
when the recorded source fails. They never replace historical artwork with the
card's current media or an unrelated archived version. Removed videos and
format changes render using their historical formats.

## Risks / Follow-Ups

- An arbitrary HTTPS or IPFS failure has no inferred Arweave fallback. Supporting
  those files requires a verified mapping to the same historical asset.
- Cross-origin HTML error pages may emit a successful load event, limiting
  automatic failure detection. HTML retains the existing eight-second loading
  timeout convention and restrictive sandbox.
- Missing historical formats depend on readable content-type headers. Sources
  that block header requests or return unknown types retain the original-media
  link. Current-artwork rendering is unchanged.
- Browser regressions cover recovery and removed-video rendering with recorded
  or missing historical formats in the existing media-readonly pack. Browser
  execution and playback were not verified in this assignment, which excludes a
  local server and deployment.
