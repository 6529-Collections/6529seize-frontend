# PR Report: Content moderation controls and review queue

PR: https://github.com/6529-Collections/6529seize-frontend/pull/3791
Branch: `agent-prxt/content-moderation` -> `main`
Related PRs: [Backend PR #1937](https://github.com/6529-Collections/6529seize-backend/pull/1937)

## Summary

Adds independent report, hide, and block controls; persistent content preferences; global moderation tombstones; and a role-gated occasional-moderator queue across desktop and mobile drop surfaces.

## What Changed

- Consolidates personal controls into a wider, simplified **Flag Content** dialog that starts with no selection; hide and block remain independent, while selecting report clearly includes the personal hide action.
- Shows a compact reporter-only **Reported** or **Reviewed** control inside the specific post through pending and resolved states, while resolved allowed reports explicitly read **Reviewed · No action taken**. Its tooltip exposes the full state, click/tap opens report details, duplicate open reports remain prevented, and confirmation-backed withdrawal leaves the post hidden.
- Replaces the resolved Flag Content form with a dedicated report outcome view: open reports can be withdrawn, while reviewed reports show **No action taken** or **Content removed** without stale report, hide, or block choices.
- Applies hide and block presentation changes immediately with action-specific rollback, including every visible post from a newly blocked author.
- Keeps personally hidden and blocked-author post content in its original layout under a strong, inert blur with centered **Hidden · Reveal · Unhide** and author-aware **Blocked · Reveal · Unblock** controls. Reveal is temporary and request-free, exposes **Hide again** alongside the persistent Unhide or Unblock action, and persistent actions remain optimistic with rollback.
- Shows a red-tinted **Blocked** status beside the handle on blocked profile pages, keeps Direct Message available, and places confirmation-backed **Unblock** where **Follow** normally appears. Brain activity keeps each post's normal height and visible Wave context while the content remains blurred until temporarily revealed.
- Makes the muted avatar and handle on blocked-post overlays link to the author's public profile, with keyboard focus and an explicit accessible name.
- Consolidates profile **Mute notifications** or **Unmute notifications** and **Block profile** into one icon-labelled responsive actions menu: desktop uses the overflow control, while mobile browsers and the mobile app use the same actions in a bottom sheet.
- Keeps one-to-one direct messaging available under normal admission rules while treating the blocker's existing and future conversation as muted and deprioritized, redacting blocked-author messages, and suppressing their notifications and unread counts without disclosing the block.
- Keeps group conversations active while hiding and silencing only the blocked author's activity for the blocker; other members continue to behave normally.
- Removes success toasts for personal hide, unhide, block, and unblock actions while retaining report confirmations and actionable error/partial-failure feedback.
- Prevents any reveal of globally quarantined or removed content and covers full drops, parts, replies, and quotes. Primary Wave chat keeps author, timestamp, and Wave context while replacing only the unavailable body with stable copy, so optimistic updates and refreshes no longer produce different labels. The shared gate also verifies that an author-only presentation still belongs to the active profile, preventing stale profile-scoped reply or quote data from exposing removed content after a profile switch.
- Keeps removed reply and quote tombstones actionable so they load, scroll to, and highlight the original post context without exposing redacted content.
- Keeps removed reply and quote previews fail-closed during a cold Wave reload: active-Wave hydration takes precedence over stale drop-detail cache and early not-found responses, so neither the original body nor a transient **Drop not found** state can flash before the moderated tombstone arrives.
- Treats missing moderation presentation data as unavailable, lets authors see their own moderated posts when the API explicitly permits it, and prevents optimistic restore state from overriding server redaction.
- Labels an author's own quarantined or removed post as visible only to that author without exposing report identity or details; moderators use the preserved WatchTower evidence instead of the ordinary Wave rendering.
- Keeps locally authored optimistic posts visible in their normal layout while the create request is pending without weakening fail-closed handling for server drops.
- Classifies pre-publication rejections by structured HTTP status, keeps model/backend wording out of user-facing toasts, clamps displayed confidence, and records the source-locale fallback debt.
- Documents the generalized structured-private-data policy for payment-card and US Social Security number signals, including permissive treatment of clearly labelled fictitious, sandbox, test, example, redacted, or documentation data.
- Combines notification, messaging, blocked-profile, and personal report-history settings on a responsive, full-height `/preferences` page with explicit **Notifications & messages**, **Blocked Profiles**, and **Reports** tabs. The caller-scoped Reports view shows each reported post from a sanitized immutable snapshot, keeps media and files collapsed by default, preserves a linked Wave name and picture after removal, links visible posts to the exact Wave or direct-message context, and supports public outcomes and open-report withdrawal without exposing AI assessments, reply-parent evidence, internal notes, moderator identity, or other reporters.
- Replaces the separate profile-menu content-preferences row and profile-preferences dialogs with one sliders-icon Preferences entry across desktop, mobile, and the current user's profile page.
- Shows the permission-gated **WatchTower** item only in the primary desktop and mobile side navigation—not the profile menu—with the updated transparent-cutout icon, while `/content-moderation` uses the **WatchTower - Content Moderation** page and metadata title.
- Prevents the no-access state from flashing while moderator identity and permissions hydrate.
- Splits WatchTower into counted **Open reports**, **Resolved reports**, and **Suspended profiles** tabs, with centralized reinstatement for suspended authors.
- Shows report content/context, author, reporting profile, reasons/count, reported media/files, a readable AI summary with expandable evidence, current state, and audit history to authorized moderators.
- Omits the neutral AI category `NONE` and labels substantive classifier output as **Potential category**, keeping the moderator decision authoritative.
- Replaces unexplained or inert-looking moderation controls with one explicitly described decision selection and **Apply decision** action; moderator notes are optional and author suspension remains a separate confirmation-backed action.
- Paginates the moderator queue with explicit Load more behavior and shows current author identity plus report time on every item.
- Applies moderation gates across leaderboard card/list/grid/gallery variants, winner and podium views, boosted inserts, quick vote, user masonry, and standalone drop views as well as the main feed surfaces.
- Refreshes queue and drop presentation caches after profile decisions, omits unavailable AI confidence, gives unblock controls unique accessible names, and keeps reply tombstones/actions unclipped.
- Makes report withdrawal use the response-bearing DELETE contract and closes the dialog after success instead of leaving an apparently inert confirmation state.
- Keeps the composer recoverable after a moderation rejection or guidelines-preflight failure, and skips unavailable Quick Tags lookups entirely for plain drafts that contain no mention alias so Post/Enter cannot silently stop before the drop request.
- Keeps the Wave composer below the repository size-debt threshold by moving its prop contract into a focused type module, uses native status output for posting restrictions, and preserves explicit keyboard semantics on actionable quote containers.
- Checks the active profile's posting status before rendering every Wave composer, reserves the final composer geometry with a quiet motion-safe loading skeleton, replaces suspended composers with a compact responsive **Profile suspended · Posting disabled** notice and support guidance, fails open to backend authority when the lookup is unavailable, and immediately updates the profile-scoped cache after a structured suspension rejection.
- Keeps valid saved sessions usable without an active wallet connection, and repairs expired-auth handling for connected profiles: account, profile, role, and active selection remain intact, signing availability is checked before invalidating the expired session, and the signing flow reopens only when it can safely continue.
- Clears viewer-scoped Wave, feed, drop, leaderboard, and profile-drop caches when the active profile changes; aborts in-flight old-profile feed and pagination requests; discards queued stale Wave updates; and prevents previous-profile placeholder data from leaking moderation state into the newly selected profile.
- Keeps the authentication action implementation below the repository size-debt threshold by separating its shared action contracts into a focused type module without changing runtime behavior.
- Adds moderator-only **Suspend Profile** and **Reinstate Profile** actions to public profile menus, including personally blocked profiles, while keeping global moderation state independent from the moderator's private block state.
- Keeps Wave drop interaction gating in a focused moderation hook and uses concrete imperative-ref typing in the Quick Tags recovery coverage.
- Expands the standalone feature guide and Help Bot corpus to cover pre-publication decisions, posting suspension, personal visibility controls, global moderation, recovery behavior, and user-facing entry points.

## Frontend Impact

- Routes/views: Adds `/preferences` and `/content-moderation`; `/content-preferences` redirects to `/preferences?tab=blocked-profiles`, while the legacy `?tab=content` query remains compatible.
- Components: Adds shared moderation actions, report dialog, tombstone gate, personal state, and moderator access hooks.
- Generated API/client: Adds the moderation endpoint models and presentation fields from backend PR #1937.
- User-visible behavior: One Flag Content entry with report-plus-hide, hide-only, and block choices; visible report lifecycle status and withdrawal; immediate personal visibility updates; blurred hidden/blocked previews; temporary per-post reveal; inline persistent undo actions; unified preferences; and non-revealable global tombstones.

## Config / Env

No frontend-specific configuration is added. Backend PR #1937 must be deployed first so the moderation endpoints and response fields are available.

## Release Notes

Users can open one Flag Content dialog to report and hide, hide only, block, or combine report and block. Reported posts show their review status and open reports can be withdrawn without automatically restoring the post. Hidden and blocked-author posts update immediately, retain their original layout under a strong blur, and offer temporary Reveal plus persistent Unhide or Unblock actions. Notification, messaging, and blocked-profile settings now live together under Preferences. Authorized moderators receive dedicated open, resolved, and suspended-profile WatchTower views with explained decision controls.
