# PR #4555 — Staging E2E contracts and Safe Collecting layout

The critical-shell readiness checks now select headings within `main`, avoiding the hidden legacy-browser notice while retaining the existing page-specific assertions.

The English and German TDH guide checks recognize the Explained shell and require its exact localized heading and navigation link. The previous guide contract remains required when that shell is absent, because the redesign is currently on shared staging but not main. Remove the old guide fixtures once that rollout is complete. Timeouts, retries, suite selection, and wallet behavior are unchanged.

## Acceptance

- EMMA, App Wallets, notifications, messages, and Block Finder reach their visible page headings using readiness scoped to `main`. These route checks do not assert the legacy-browser notice's visibility.
- Both TDH guide versions require their correct translated title and navigation; unknown titles, missing translations, and incorrect redesigned link destinations fail.
- Narrow-screen overflow assertions and signed-out access checks remain intact.

## Safe Collecting layout

This PR also fixes the French Safe Collecting button overflow previously reproduced on staging and production. Setup-step, main setup, and disconnected-wallet buttons constrain their width and wrap their labels while preserving the complete text and existing actions. Setup-step buttons grow beyond their 36px minimum height when needed.

Long words in Safe Collecting text can break across lines when they would otherwise exceed their container. This fixes German compound words overflowing setup instructions and tool descriptions on narrow screens, without shortening translations or hiding content.

The existing 2px overflow tolerance remains unchanged. French and German regression coverage includes both setup tabs at 375px and 320px. The French button changes were consolidated here from the superseded PR #4556.

## About navigation and TDH overview

The About contents button is disabled in server HTML until hydration attaches its interaction. This prevents an apparently usable button from losing its first click. Its original menu contents assertions remain, with additional coverage for scripts arriving late.

TDH overview checks recognize the Explained shell, require its exact current title, and verify the calculation, specification, boost-history, and glossary destinations. The calculation link must navigate to the correct page. The legacy overview still requires its original heading, boosts section, and reference links. Remove the legacy branch after the redesign reaches production.

## Collectors tooltip interaction coverage

The Collectors responsive test exercises hover and keyboard focus as separate interactions. After checking that Escape dismisses the hover tooltip, it moves the pointer away and waits for the tooltip to leave the DOM before focusing the CSV button. CSS makes the closing tooltip invisible before dismissal is complete, so visibility alone is not a complete reset between the two interactions.

Hover, keyboard focus, Escape dismissal, focus retention, responsive metrics, CSV controls, and overflow assertions remain required. No fixed sleeps, retries, tolerance changes, or skips were added. This is test isolation; it does not change the production tooltip or claim to fix a reproduced user-facing defect.

This maintenance is separate from the selected-drop SEO implementation in PR #4479.

## Legacy Wave message links

The shared social-readonly test now chooses an existing message from the environment's public chat wave. It observes the legacy redirect at navigation commit, requiring the exact wave path and message serial while removing the legacy `wave` parameter. It then requires a successful target-history lookup, URL cleanup, and the selected message visibly in the chat viewport. A target-identity artifact records the wave and serial for diagnosis.

The user-approved contract is to reach the intended message while allowing the documented one-time URL cleanup. Keeping `serialNo` in the address bar after hydration is not that contract. Mutation protection, overflow checks, retries, timeouts, and staging/production pack selection are unchanged. This includes the redirect observation from #4567 and adds the actual message-arrival assertion.

An initial staging desktop check lost the target before the viewport assertion; the exact target and subsequent diagnostic runs passed without weakening the assertion. The cause of that intermittent result remains unconfirmed; this change does not claim a product-level scrolling fix or guarantee a fully green E2E suite.
