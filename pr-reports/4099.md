# GIF previews and original playback

PR: [Frontend #4099](https://github.com/6529-Collections/6529seize-frontend/pull/4099)

Related: [Backend #2118](https://github.com/6529-Collections/6529seize-backend/pull/2118)

Drop previews and profile banners request versioned animated GIF derivatives,
with fallback to legacy previews. The expanded viewer offers an **HD** toggle in
its top-right toolbar, before fullscreen. Its tooltip switches between **View
original** and **View optimized**; it matches the other white toolbar icons by
default, highlights when the original is selected, and resets for each gallery
item. Opening the viewer or navigating its gallery
does not automatically download originals. Inline GIFs have no added badge or
quality control. While the original loads, the optimized preview stays visible
under a small loader. The viewer swaps only after the original is ready. Switching
back or navigating cancels the pending selection; stale load events are ignored.

Banner display/edit previews, image-viewer documentation and product help
knowledge follow the same behavior. Other image consumers and generated API
models are unchanged. Core receives these frontend changes through its normal
renderer sync; this PR does not modify or release Core.

## Rollout Dependency

Deploy the companion backend's `mediaResizerLoop` before this frontend. The new
cache keys bypass old static derivatives without invalidation. The worker is
currently listed as production-only in the backend service catalog.

## Risks / Follow-Ups

Legacy fallback previews can remain static; explicit playback downloads the full
uploaded GIF after user action. Browser coverage includes a synthetic animated
fixture, but actual browser layout/playback verification remains outstanding
because no local server or deployment was authorized. Verify it during rollout.


Non-GIF images retain the existing scaling helper. Original-load failures return
to the optimized preview, announce the error and keep focus on HD. The error
appears as a warning icon in the HD button plus its tooltip, with no overlay on
the artwork. Retrying restores HD, so failure is distinguishable without color.
The persistent error announcement and the button's error description use
separate elements. Actual assistive-technology verification remains a rollout
check; component coverage verifies the description, retry announcement and focus.

GIF URL selection lives in `helpers/gif-preview.helpers.ts`. The shared image
helper and its existing test mocks retain their original contract, including
curation-card image and video-thumbnail consumers.

Versioning and legacy fallback change only the derivative segment next to the
filename, preserving similarly named parent folders and query/fragment data.
