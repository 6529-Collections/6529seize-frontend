# PR Report: Archive Frontend Release Bus Integration

PR: https://github.com/6529-Collections/6529seize-frontend/pull/3709
Branch: `agent-prxt/archive-frontend-release-bus` -> `main`
Related PRs: None

## Summary

Removes Release Bus as a dependency of the active frontend deployment paths
while preserving exact-SHA artifacts, serialized environment mutation,
production downgrade protection, and automatic post-deploy E2E.

## What Changed

- Archives the frontend Release Bus workflows, scripts, contracts, tests, and a
  curated set of exact pre-change deployment guidance under
  `ops/archive/frontend-release-bus-integration/` from commit
  `a9fa98482c000e86161f670c8120c7801046fd01`.
- Keeps archived workflow YAML outside the executable root
  `.github/workflows/` directory.
- Makes a push to `1a-staging` the direct exact-SHA staging build and deploy
  path, followed by automatic staging E2E for the successful deploy run.
- Keeps production as a manual `Web Deploy - PROD` run on `main`, with an exact
  artifact builder, an independent read-only verifier, stale-main and downgrade
  guards, deployment, and automatic production E2E.
- Retains the reusable artifact archive and extraction defenses in a neutral
  active helper while archiving obsolete operation-selection behavior.
- Updates CI contracts, artifact portability reporting, documentation, agent
  instructions, and the frontend deployment skill for the direct paths.

## Frontend Impact

- Routes/views: Not affected.
- Components: Not affected.
- Generated API/client: Not affected.
- Deployment behavior: Frontend staging and production no longer require
  Release Bus readiness, operation identity, authority, or completion state.
- User-visible behavior: Not affected outside deployment operations.

## Config / Env

No new API, database, queue, service, authorization system, environment
variable, or credential is introduced. Existing staging and production
workflow names, entry points, runner variables, AWS credentials, concurrency
groups, and E2E secrets remain in use.

## Release Notes

Frontend deployments now use direct repository-owned exact-SHA workflows for
staging and production. Backend Release Bus and Deploy Hub are unchanged.

## Risks / Follow-Ups

Production remains manually dispatched and fails closed if `main` advances
while a run is queued or if the announced production version is not an ancestor
of the selected target. Restoring the archived integration would require a
separate reviewed change that reconciles current frontend artifact safeguards
with the corresponding backend contracts.
