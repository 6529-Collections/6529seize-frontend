# PR Report: Configurable server Ethereum RPC

PR: [#3911](https://github.com/6529-Collections/6529seize-frontend/pull/3911)

## Summary

Server-owned ordinary Ethereum mainnet reads use one configurable
`ETHEREUM_RPC_URL`. Alchemy NFT REST APIs and metadata fallbacks remain on the
separate server-only `ALCHEMY_API_KEY`.

## What Changed

- A shared lazy Viem client replaces default and hard-coded mainnet transports
  in the server-owned Open Graph handlers. Browser wallet transports are unchanged.
- Staging passes its dedicated Alchemy NFT API key through the private runtime
  secret store into PM2, without adding it to build or browser configuration.
- Dead-code cleanup was completed separately in
  [PR #3915](https://github.com/6529-Collections/6529seize-frontend/pull/3915).

## Config / Env

- Production: configure `ETHEREUM_RPC_URL` in GitHub Actions with a complete
  Ethereum mainnet HTTP(S) RPC URL; retain the existing `ALCHEMY_API_KEY` secret.
- Staging: configure `STAGING_ETHEREUM_RPC_URL` and `STAGING_ALCHEMY_API_KEY` in
  GitHub Actions. Deployment supplies them as `ETHEREUM_RPC_URL` and
  `ALCHEMY_API_KEY` respectively. Missing or empty required values stop deployment.
- The old EC2 checkout `.env` is not a configuration source for the standalone
  staging release. These values must be supplied through the workflow.
- Initially use Alchemy for the RPC URL. Switching ordinary-RPC providers later
  requires changing the corresponding URL secret and redeploying; NFT APIs
  remain Alchemy-specific.
