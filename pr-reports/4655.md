# PR Report: Stable Windows touch E2E targeting

PR: [FE #4655](https://github.com/6529-Collections/6529seize-frontend/pull/4655)
Branch: `agent-prxt/fix-win8-touch-e2e-race` → `main`

## Summary

Keep the Windows touch-input browser regression on one hydrated message instead
of repeatedly selecting whichever row is last. This addresses failures that
occurred during scrolling before the input-mode assertions could run.

## What Changed

- Pin the test target by message serial number within the main landmark,
  retaining the existing touch capability requirement.
- Let the normal trusted tap handle scrolling and row replacement without
  forced input or a separate stale-node scroll action.
- Pair long-press start and end on the same node, including when a newer message
  arrives during the gesture.
- Cover delayed replacement, scroll-triggered replacement, and arriving rows
  with self-contained browser regressions in the existing input-detection pack.
- Preserve the touch/mouse classification and action-sheet assertions, retry
  policy, and timeout budgets. Product behavior and backend services are unchanged.

## Risks / Follow-Ups

The self-contained browser harness exercises target selection and gesture
pairing. The full deployed application journey remains separate evidence; this
change does not claim to fix unrelated staging availability or navigation errors.
