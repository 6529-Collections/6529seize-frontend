# Browser compatibility notices and page-heading checks

Older iOS/browser engines see an upgrade notice instead of an application shell they cannot parse. Modern browsers keep both notice variants hidden.

The notices add two h1 elements outside the page main landmark. Museum institutional-practice and other page tests now inspect the visible page heading inside main using role selectors, preserving the single page-heading guarantee while excluding hidden compatibility notices. Content-specific heading assertions remain unchanged.

The affected Museum and page specs were reviewed, with the shared Museum check covering desktop and mobile. A standalone Chromium document reproduced three DOM headings, verified one visible main heading, and verified that a second visible main heading is still detected. The full deployed Museum pack needs a staging rerun after this branch is integrated; no local application server was started.

The minimum-iOS companion is [Mobile #26](https://github.com/6529-Collections/6529-core-mobile/pull/26). This update does not authorize a production rollout.

The probe fixture’s notice HTML is pinned to the server-rendered notice so a markup or wording change cannot silently invalidate the device evidence. The device probe still collects engine outcomes rather than requiring a predetermined classification; document replacement intentionally exercises parser-inserted scripts.

The iOS upgrade notice names the app in both instructions: 6529 Mobile on production and 6529 Staging on non-production builds, using the configured site endpoint.
