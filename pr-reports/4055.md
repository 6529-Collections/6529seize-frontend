# PR Report: Prevent desktop layout flash during native startup

PR: https://github.com/6529-Collections/6529seize-frontend/pull/4055
Branch: agent-prxt/fix-native-startup-layout-flash -> main

## Summary

Native iOS and Android launches show a dark native loading shell until the app layout mounts, instead of briefly exposing the desktop sidebar. Public server-rendered content and wallet-independent startup are preserved.

## What Changed

- Detect native runtimes synchronously during document parsing, including bridges available before the Capacitor JavaScript package initializes. Browser user agents and stored cookies do not activate the guard.
- Keep the initial server content mounted for hydration while concealing its web layout in native runtimes. Reveal native content when layout selection resolves, without waiting for wallets or a fixed delay.
- Reserve native header and bottom-navigation space during startup. Preserve the version-update reload cover and its handoff to the native shell.
- Update app-header documentation and Help Bot knowledge.

## Design Decision

The bootstrap is a synchronous inline script with critical inline CSS. Deferring it until the Next runtime loads would allow the unwanted desktop paint. Hydration-safe device hooks and the existing Wagmi/AppKit startup remain unchanged.

The standalone `/access` and `/restricted` pages intentionally remain outside the guard: they never mount desktop or native navigation. Their content stays available immediately, and subsequent navigation enters the native shell directly.

The standalone browser fixtures declare the application's mobile viewport settings. Without that metadata, mobile Chromium uses a 980px layout viewport despite the test's 390px device size, producing a fixture-only loading-shell width failure.

## Risks / Follow-Ups

Physical-device cold starts and a complete native-app launch still need confirmation. Browser coverage exercises the actual startup boundary and styles; component coverage exercises real device hooks and layout hydration.

Production compilation remains unverified locally: Turbopack rejected this worktree's shared dependency symlink because it points outside the project root.
