# PR Report: Mobile lab production trigger

PR: [#4432](https://github.com/6529-Collections/6529seize-frontend/pull/4432)
Branch: `agent-prxt/fix-mobile-lab-trigger` → `main`

## Summary

Restore automatic production Mobile lab measurements. Successful production
deployments supply a dynamic `Production deploy <sha>` title, which the lab
previously rejected before measuring the site.

## What Changed

- Identify deployment workflows by their exact file paths for staging and
  production routing; reject other paths even if their titles look familiar.
- Use `mobile-lab-staging` and `mobile-lab-production` concurrency groups for
  both automatic and manual runs. Keep active runs running.
- Preserve successful same-repository deployment guards, manual page/target
  inputs, read-only permissions, and report-only budgets.
- Add routing and concurrency regression coverage and register it for future
  workflow-only changes in the filesystem-contract selector.

## Config / Env

No new environment variables or secrets. The production workflow identity is
`.github/workflows/build-upload-deploy-prod.yml`; staging uses
`.github/workflows/deploy-staging.yml`.

## Operator Follow-Up

Once the fix is on `main`, start a fresh **Mobile lab** workflow dispatch on
`main` with `target=production` and `pages=home,waves,meme,museum`. This measures
the currently deployed site without redeploying. Rerunning an old failed run
uses its original workflow revision. See the
[Mobile lab runbook](../ops/scripts/mobile-lab/README.md#running-it).

Automatic production mobile performance reports resume after successful web
