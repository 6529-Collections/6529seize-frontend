# PR Report: Harden production environment artifacts and restore GIFs

PR: https://github.com/6529-Collections/6529seize-frontend/pull/3477
Branch: `agent-prxt/harden-production-env-and-gif-config` -> `main`
Related PRs: None

## Summary

This change prevents production packages from shipping with a non-production
API endpoint and restores the GIF action when its browser-public GIPHY
configuration is available. When GIF configuration is unavailable, the control
remains visible and explains the temporary unavailability instead of silently
disappearing.

## What Changed

- Reject production review/deploy artifacts unless their baked runtime endpoint
  is exactly `https://6529.io` and their GIPHY configuration is nonblank.
- Supply the repository GIPHY Actions variable to PR, Release Bus v2 preflight,
  and production build workflows.
- Keep the GIF action discoverable and reuse the existing unavailable state for
  missing configuration or provider failures.
- Localize the GIF action label and tooltip across the supported locale set.
- Add production postdeploy coverage that rejects any visible environment
  badge.

## Frontend Impact

- Routes/views: production home postdeploy validation now asserts that no
  environment badge is rendered.
- Components: Waves drop actions and the GIF picker retain the GIF control when
  configuration is missing and show a localized unavailable state.
- Generated API/client: Not affected.
- User-visible behavior: GIF selection is restored for correctly configured
  builds; configuration/provider failures are visible rather than removing the
  action.

## Config / Env

- `BASE_ENDPOINT`: pre-existing required public runtime value owned by the
  frontend build workflows. Production packages must bake
  `https://6529.io`; any other value now fails packaging before deployment.
- `GIPHY_API_KEY`: pre-existing browser-public integration value, now required
  for production artifact packaging and supplied through the repository GitHub
  Actions variable of the same name. A blank or missing value fails production
  packaging; at runtime, the GIF picker displays its unavailable state rather
  than disappearing.

## Release Notes

Production artifacts now fail closed when they contain the wrong API
environment. The Waves composer again exposes GIF selection in configured
builds and gives users a clear unavailable state if the provider cannot be
used.

## Risks / Follow-Ups

- The GIPHY browser key and provider allowance remain client-side/external by
  design. A server-side proxy, quota telemetry, and provider-level hardening are
  intentionally deferred to a later change.
