# Preserve wave request cancellation

PR: [#4130](https://github.com/6529-Collections/6529seize-frontend/pull/4130)

Cancelling a newest-messages request while its response body is being read now preserves the original `AbortError`. The shared API parser previously replaced it with a generic JSON parsing error, causing wave callers to log an expected cancellation as a message-fetch failure.

The shared parser rethrows abort exceptions unchanged, allowing existing wave cancellation handling to recognize them. Genuine malformed JSON still produces the descriptive parsing error. Successful responses, request scheduling, and retry configuration are unchanged.
