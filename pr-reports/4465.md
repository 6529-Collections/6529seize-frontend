# Submission GIF animation

PR: [Frontend #4465](https://github.com/6529-Collections/6529seize-frontend/pull/4465)

On desktop, the primary GIF artwork in the Memes single-submission view tries both animated
CDN preview sizes before automatically loading the original animation. An
available legacy preview remains visible until the original is ready. HD reflects
the selection and shares it with the artwork popup.
The trigger is failure of both versioned animation previews. Legacy and external
previews do not guarantee animation; the original may therefore be selected even
when such a fallback happens to animate. This is intentional in the single-artwork
view to ensure the submission's animation is available without an HD discovery step.
GIFs with no eligible preview source also request the original automatically on
desktop; repeated mount effects and rerenders do not repeat that request.
Phones, tablets, and native mobile apps keep bounded previews and manual HD,
including when a tablet reports a desktop user agent. Automatic loading waits
for device detection to resolve. Desktop web and desktop app sessions retain
automatic fallback. The improved artwork loading indicator applies everywhere.

Choosing **View optimized** cancels or reverses original loading and prevents
another automatic switch for that artwork. A failed automatic original load
preserves the preview and existing HD error/retry controls. Changing artwork
resets the choice. Feeds, grids, ordinary thread viewers, supplemental images,
and still artwork retain their existing quality-selection behavior.

GIF artwork in submission, leaderboard, participation, and winner cards uses a
subtle backdrop across its reserved media frame with a centered spinner. The
single-submission view keeps the same loader through preview rejection and original
loading (automatic on desktop or manually selected with HD on mobile), including
when a legacy preview is ready. There is no separate visible
Loading original GIF stage. Failure or HD cancellation clears the loader when a
fallback preview is available. The spinner respects reduced motion and leaves HD
accessible. Artwork cards keep their existing animation limits; ordinary thread/DM
attachments retain the compact placeholder. Still-image and other media loaders
are unchanged.

Automatic original playback can consume more bandwidth and device memory in this
desktop single-artwork view. Backend processing limits are unchanged. Documentation and
Help Bot knowledge describe the scoped exception. Desktop and mobile artwork
regression cases run in a dedicated submission-artwork CI job, with a separate
server/build output and timeout budget. Existing competition coverage remains
selected and its tests and assertions are unchanged.

Museum CI dependency installation allows slow package downloads and waits up to
five minutes for a package-manager lock before retrying. Setup still fails when
neither installation attempt succeeds; no lock is deleted and no package-manager
process is killed.
