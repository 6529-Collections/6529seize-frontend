# PR Report: Collection balances during infinite scroll

PR: https://github.com/6529-Collections/6529seize-frontend/pull/4084
Branch: agent-prxt/lazy-load-balances -> main

## Summary

Fix ownership indicators incorrectly switching from `SEIZED` to `UNSEIZED`
when more collection cards load. Balance retrieval now consumes every API page
and caches a complete snapshot per profile consolidation and collection contract.

## What Changed

- The Memes, Meme Lab, and Meme Lab collection grids reuse the same complete
  balance snapshot when scrolling, sorting, and filtering.
- Incomplete balance responses remain loading; failed pages display `N/A`
  instead of interpreting missing rows as zero balances.
- Malformed or nonterminating pagination fails with `N/A`, without publishing
  partial balances. Requests stop after 100 pages or an empty intermediate page.
  Only an explicit null next-page field completes a snapshot; missing or invalid
  pagination fields report unavailable balances.
- Profile and contract changes use separate cache entries and cancel abandoned
  requests. Refreshes replace old holdings so transferred tokens can become
  unseized correctly.
- Gradient requires no change because its ownership badge uses token-owner and
  connected-wallet matching independently of the collection balance API.

## Release Notes

Owned cards retain their ownership indicators while browsing additional pages
of The Memes and Meme Lab.

## Risks / Follow-Ups

Initial balance loading retrieves all holdings for the selected contract in
sequential pages of 100. Profiles with many holdings may wait longer for the
initial snapshot; later grid pages reuse it without fetching balances again.
The 100-page safety limit supports up to 10,000 ownership rows at the requested
page size; exceeding it reports unavailable balances rather than truncating them.
