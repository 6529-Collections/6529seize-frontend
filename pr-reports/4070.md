# PR Report: Museum Collection HTTP redirects

PR: [#4070](https://github.com/6529-Collections/6529seize-frontend/pull/4070)

Branch: `agent-prxt/museum-rights-http-redirect` → `main`

## Summary

Legacy Collection accession URLs now return an empty HTTP 308 to their canonical Work URL before rendering the application. Previously, the Museum's streaming boundary could send a 200 application shell followed by a browser redirect. Production Rights failures recorded simultaneous startup-request cancellations during that navigation, even though the destination's rights content rendered correctly.

## What Changed

- Replace the redirect-only Collection page with a GET route handler using the existing accepted-publication and permanent-Collection membership lookup.
- Preserve the canonical destination. Unknown or non-Collection objects, and unavailable publications, return a plain HTTP 404. Both response types use `Cache-Control: no-store` so an earlier lookup cannot override a later publication decision.
- Keep metadata and all visible Museum content on the canonical Work page.
- Require the Rights browser journey to verify an actual 308 redirect chain and the canonical destination, while preserving its content, layout, console-error and failed-response checks.
- Move the alias into the Museum registry's support-file inventory; the page-only route manifest no longer lists it, while browser coverage remains in the existing Rights and Inside the System packs.
- Preserve deleted files' surface ownership from the base commit when checking a change set. The registry still rejects unregistered paths and validates the complete current inventory; converting a page into a route handler no longer causes a false unmapped-file rejection.
- Expose client readiness on the Work-to-study link after hydration. The Inside the System journey waits for that specific link and verifies that navigation preserves the browser document. Visible server HTML alone is insufficient: clicking it before Next's navigation handler is ready can replace the document and cancel startup requests. The link's URL, copy, styling, and server-rendered anchor remain the same.

## Risks / Follow-Ups

The transport change removes the intermediate application shell implicated by production evidence. Staging can validate the new redirect and client-navigation contracts, but a staging pass alone does not establish that production flakiness is resolved. That requires reproduction under comparable conditions or repeated clean first-attempt production Rights results after deployment. Do not treat a pass obtained only after retries as that confirmation.

PR #4051 is included through the main-branch merge. Its local country-check fixture remains limited to local tests; staging and production still use live requests. The redirect fix does not expand console-error allowances.
