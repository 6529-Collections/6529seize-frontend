# PR Report: Notifications and wave entry loading

PR: [#4407](https://github.com/6529-Collections/6529seize-frontend/pull/4407)

## Summary

Notifications now use one loading surface throughout route preparation, wallet restoration, profile loading and the first feed fetch.

Direct drop links open the detail surface immediately while the requested drop loads. Previous cached drops cannot flash during the handoff, and failed loads offer retry and close actions. The existing Default, Memes and Quorum submission layouts are retained. Ordinary wave entry keeps the outer layout’s sidebar placeholder; direct drop entry shows only the detail loader. Pending panels focus Close, scope Escape to their own surface, and preserve keyboard focus through dismissal or the loaded-detail handoff. Default and Memes panels also expose retry when wave metadata fails.

Public waves retain their server-rendered post text and links in a compact chat layout. The preview remains until the interactive thread renders, including through auth restoration, avoiding the separate posts-card view and discovery skeleton. Existing server feed seeding remains in place. Only the matching active wave can release its preview. Failed drop-thread requests show retry recovery while retaining already loaded replies.

## Scope

Frontend UI and loading handoffs, localized loading/error copy, product documentation and help-index updates. Existing API contracts and server-side visibility filters are preserved. Interactive chat waits for wallet/profile resolution even when the URL already selects a wave, preserving the previous layout’s auth gate.

## Risks / Follow-Ups

Full application browser verification of cold navigation, wallet restoration and native overlays remains to run.
