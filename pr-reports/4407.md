# PR Report: Notifications and wave entry loading

PR: [#4407](https://github.com/6529-Collections/6529seize-frontend/pull/4407)

## Summary

Notifications now use one loading surface throughout route preparation, wallet restoration, profile loading and the first feed fetch.

Direct drop links open the detail surface immediately while the requested drop loads. Previous cached drops cannot flash during the handoff, and failed loads offer retry and close actions. The existing Default, Memes and Quorum submission layouts are retained.

Public waves retain their server-rendered post text and links in a compact chat layout. The preview remains until the interactive thread renders, including through auth restoration, avoiding the separate posts-card view and discovery skeleton. Existing server feed seeding remains in place.

## Scope

Frontend UI and loading handoffs, localized loading/error copy, product documentation and help-index updates. Existing API contracts and server-side visibility filters are preserved.

## Risks / Follow-Ups

Full application browser verification of cold navigation, wallet restoration and native overlays remains to run.
