# PR Report: Drop Forge Contract Admin Management

PR: [Frontend #4160](https://github.com/6529-Collections/6529seize-frontend/pull/4160)
Branch: `agent-prxt/drop-forge-onchain-admins` -> `main`
Related PRs: [Backend #2134](https://github.com/6529-Collections/6529seize-backend/pull/2134)

## Summary

Drop Forge lists its creator owner/admins and provides a confirmed grant/revoke
workflow. Approved on-chain admins gain Launch and tracking access without an
environment-list change; craft and admin-management privileges stay separate.

## What Changed

- `Contract Admins` appears below the Craft/Launch cards for every wallet with
  landing access in a matching static card. Owner is first; Owner/Admin pills and
  available mainnet ENS names accompany full addresses. Pills sit above a
  wrapping ENS/address line; the creator contract links to its chain's Etherscan.
  Duplicates are removed.
- Header Add Admin unfolds its inline form above the list; Cancel resets it and
  restores focus. Refresh has a minimum 1.5-second spinner and waits for both
  reads. Refresh/Revoke use shared app tooltips rather than native browser titles.
- Admin controls use scoped, consistently sized buttons and icons. Shared
  transaction subtitles use the full header width, preventing unnecessary
  desktop address wrapping while retaining mobile wrapping.
- Launch/tracking accepts configured claims admins, creator owner, and approved
  on-chain admins. Craft remains distribution-admin-only.
- Add/Revoke controls require owner or configured claims-admin access. Add
  accepts address/ENS and confirms the resolved address; invalid, unresolved,
  zero, owner, and duplicate additions are rejected. Owner revocation is absent.
- Drop Forge opts into forward resolution of editable ENS labels. Edited names
  invalidate pre-sign review, and pasted/edited wallet suffixes cannot override
  the resolved name. Pending/failed/missing lookups block submission. Other ENS
  input consumers retain their existing default behavior.
- Writes use the active creator/chain, intended signer, existing ENS input,
  wallet connection, and transaction dialog. Changed signing context cancels
  pending requests; duplicate submissions and cancelled/replaced receipts do
  not report false success. Successful receipts refresh creator permission reads.
- Only the pre-sign review opts into pending-state dialog dismissal; actual
  transaction dialogs preserve existing behavior.
- Invalid admin input is associated with its announced error and marked invalid.
  New admin copy and accessible names use the existing locale message system.
- A repriced transaction reports its mined replacement hash; cancellation or a
  different replacement never reports a successful admin change.
- Product/help documentation covers roles, transaction recovery, and funding:
  signer pays gas; Pay Artist transfers the signer's ETH; admin approval does
  not redirect mint revenue. Backend OpenAPI is synchronized.

## Config / Env

No new variables. Existing claims/distribution wallet lists keep their meanings.
Mainnet ENS resolution is separate from the active creator's chain selection.

## Risks / Follow-Ups

- The contract only permits its owner to approve/revoke. Configured non-owner
  claims admins intentionally see controls for testing; their writes still fail.
- Revoking on-chain access does not remove an independent configured claims
  admin grant. No environment list or ownership is changed by these controls.
- Backend `api` from #2134 must precede the frontend rollout. Sepolia action
  tracking remains unsupported even though testnet admin reads/writes are offered.
- Authenticated full-route/live-wallet validation remains outstanding; no dev
  server or live transaction was authorized. Isolated real-component layout was
  checked with project CSS at desktop and mobile widths. Message-backed admin
  copy falls back to English in other supported locales; ownership and remediation are
  documented in the Drop Forge product docs.

## Release Notes

See and manage creator admins from Drop Forge; delegate Launch operations to an
approved wallet while retaining owner-only on-chain admin management.
