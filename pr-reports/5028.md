# Mint log: sign minting writes with the device key

[Frontend PR #5028](https://github.com/6529-Collections/6529seize-frontend/pull/5028) · [Backend PR #2536](https://github.com/6529-Collections/6529seize-backend/pull/2536)

## Summary

Admin writes to the minting tables carry a signed `mint.admin` record, and collaboration invites and replies a `mint.user` record, signed by the browser's device key under the device grant it already holds. There is no new wallet prompt. The record names the action and the sha256 of the request; the API keeps it beside the change it logs. NextGen allowlist uploads also sign the CSV's sha256.

## Frontend impact

- **For people:** none while `NEXT_PUBLIC_FEATURE_MINT_SIGNED_WRITES` is off (the default). With it on, these writes send one extra request header; nothing is shown and nothing is asked.
- **Signing never blocks a write:** without a device grant, an anchor or a working key, the write goes without the record.
- **Not live yet:** no header is sent until the frontend bootstrap binds `setMintRecordContextSource`, with the principal from `signedInChainContext()` and the anchor from `fetchRecordAnchor()` (agreed with the identity frontend PR, #4992).

## Frontend deployment

1. #4994 and #4997 (signed records) are merged into main; deploy them and the backend PR's API, #2536, first.
2. This PR with the flag off.
3. `NEXT_PUBLIC_FEATURE_MINT_SIGNED_WRITES=true` once the principal source is bound. Rollback: set it to false and rebuild.
