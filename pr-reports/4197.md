# PR Report: Mobile Web Layout Flash

PR: https://github.com/6529-Collections/6529seize-frontend/pull/4197
Branch: `agent-prxt/mobile-web-layout-flash` -> `main`

## Summary

Mobile browsers previously displayed the desktop sidebar and squeezed page
content while loading application JavaScript, then switched to mobile chrome.
The browser now prepares the mobile header and full-width content before the
first paint, keeping page content mounted throughout hydration.

## What Changed

- Add a synchronous web startup bootstrap and critical layout CSS alongside
  the existing native startup guard.
- Include mobile header markup in the server shell. Keep its search/share
  interactions inactive on desktop so hidden chrome cannot duplicate shortcuts
  or retain modal state.
- Release the startup marker when React takes over the mobile layout, preserving
  later responsive changes, page state, and in-progress uploads.
- Release stale startup chrome when current capabilities resolve to desktop;
  retain it through React's initial hydration defaults to avoid another flash.
- Show a pending navigation spinner before hydration and use browser-locale
  message keys for menu labels, with the normal English fallback.
- Preserve phone overrides, touch-first tablet classification, touch-laptop
  layouts, and native app startup behavior.
- Update navigation documentation and the help corpus.

## Risks / Follow-Ups

The before-paint classifier intentionally mirrors current device-detection
rules because it runs before application modules load. Keep these rules aligned
when device classification changes.
Shared device-matrix coverage compares the before-paint script with the actual
hydrated helper, including persisted mouse evidence and blocked storage.

## Release Notes

Prevent the desktop sidebar from briefly appearing when opening 6529.io in a
mobile browser.
