# PR Report: Compact mobile update control

PR: [#4010](https://github.com/6529-Collections/6529seize-frontend/pull/4010)
Branch: `agent-prxt/reliable-update-pill` → `main`

## Summary

Mobile users get a compact green Update pill using `rocket-refresh-small.png`. The pill follows the navigation dock's measured position and existing phone scroll scale. Home continues to navigate home, and desktop web retains its existing update prompt.

## Refresh behavior

One shared version check drives the prompt and native pull-to-refresh. With an available update, a completed pull fully reloads the page through the same helper as the update button, preserving the route and wave reading position when available. Otherwise the gesture keeps its content-refresh behavior.

## Release configuration

Production requires the existing `ANNOUNCED_VERSION_ENDPOINT` to return a valid ready announcement. Missing production configuration, invalid configured endpoints, network errors, and timeouts no longer fall back to the responding server's version. Local/staging environments with no announcement endpoint retain live-instance comparison. No new environment variables are introduced.

## Risks / Follow-Ups

The original Android report of an update persisting after tapping the refresh control has not been reproduced on a device. The existing release-announcement publication and version-ordering policy remains in place. Production compilation requires runtime environment configuration that was unavailable locally; visual evidence uses an isolated component fixture rather than a live native app.
