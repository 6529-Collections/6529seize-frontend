# Signed records: sign and seal records with the device key

[Frontend PR #4994](https://github.com/6529-Collections/6529seize-frontend/pull/4994) · [Backend PR #2523](https://github.com/6529-Collections/6529seize-backend/pull/2523)

## Summary

The browser side of signed records. A person's device signs public or private records with its existing device key, under the device grant it already holds, as it signs drops. There is no new wallet prompt. Private records are sealed with a per-device sender key, which is wrapped to 6529.io's provider keys (HPKE, RFC 9180). `fetchRecordAnchor()` reads the anchor height from the API.

## Frontend impact

- **For people:** none yet. No page, hook or request uses the module; later features call it behind their own flags.
- **Shared code:** `isOwnProfileSession` moved to `lib/device-signing/own-profile-session.ts`. Signed drops behave as before.
- **API types:** `openapi.yaml` and the generated `ApiSignedRecordsAnchor` model match the backend's new endpoint.

## Risks and follow-ups

- **The anchor endpoint** answers 503 until the backend wires in the chain gateway client; `fetchRecordAnchor()` throws until then.
- **The provider public keys** are set as configuration when the first caller ships.
