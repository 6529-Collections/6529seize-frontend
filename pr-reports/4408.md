# PR Report: Deleted reports and original-post access

PR: https://github.com/6529-Collections/6529seize-frontend/pull/4408
Branch: `agent-prxt/watchtower-deleted-reports` → `main`
Related PR: https://github.com/6529-Collections/6529seize-backend/pull/2214

## Summary

WatchTower distinguishes deleted original posts from moderation visibility,
offers explicit deleted-report resolution, and provides a dedicated original
post link for both live and deleted published posts.

## What Changed

- Report cards and check detail show Deleted and Open original post. Links use
  the reported post's own identifiers and trusted relative routes, independently
  of links embedded in evidence. Deleted links explain that the original is no
  longer available; missing or invalid context has a clear fallback.
- Resolve reports — post deleted uses the existing reason, confirmation and
  safe retry controls. Saving refreshes queues, counts and the navigation
  indicator. Mark reviewed explicitly explains that it does not close reports.
- Reporter outcomes and preferences distinguish Post deleted from moderator
  removal. Saved snapshots and audit history remain private and inert.
- Synchronizes generated API models, moderation documentation and help
  knowledge. New messages use the existing en-US fallback in other locales.

## Backend Dependency

The related backend provides `RESOLVE_DELETED_REPORT`, `RESOLVED_DELETED`, and
the deleted/open-report fields. Release that backend before this frontend.
No new frontend configuration is required.

## Release Notes

Moderators can open the original reported post directly and close reports even
after it is deleted, while retaining the saved evidence and decision history.
