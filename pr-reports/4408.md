# PR Report: WatchTower review queue and deleted-post reports

PR: https://github.com/6529-Collections/6529seize-frontend/pull/4408
Branch: `agent-prxt/watchtower-deleted-reports` → `main`
Related PR: https://github.com/6529-Collections/6529seize-backend/pull/2214

## Summary

WatchTower opens a Needs review queue with one row per case requiring manual
attention, grouping a post's reports and pending check revisions. It also
distinguishes deleted original posts, offers explicit deleted-report resolution,
and links directly to live original posts. Selecting Review case keeps the full
outstanding case list alongside the selected detail.

## What Changed

- Needs review shows the server-grouped case queue, with source labels, report
  reasons/check outcomes, outstanding requirement counts and a direct Review
  case link. Review case opens the full unique-case list on the left, with the
  selected row highlighted and its evidence, report notes and remaining check
  revisions on the right. Selecting another row switches the detail. Report-only
  work remains in the list until resolved, even after Mark reviewed.
- The sidebar dot, tab badge and top summary share the server's unique manual
  review case count. Multiple reports/checks about one post count once. A
  check-only case also triggers attention. The signal refreshes every minute
  while active and after decisions; the visible case queue also refreshes while
  active. Reading a case does not clear it.
- Cases remain until all their open reports and pending checks are handled.
  Checks and Resolved reports retain history; legacy open-reports links still
  open Needs review. Failed case loads retain prior rows and offer Retry.
- Queue cards, review-list rows and check detail show a red Deleted pill.
  Open original post appears only for live originals, using their own
  identifiers and trusted relative routes, independently of embedded links.
  Deleted content has concise saved-evidence guidance; missing or invalid
  live-post context has a clear fallback. Retained post titles and textual
  parts produce useful previews without reviving expired evidence.
- One compact filter bar combines Needs review only with a separately controlled
  Filter checks disclosure. The toggle applies review status immediately while
  preserving other applied filters. Advanced edits remain pending until Apply
  filters, show Unapplied changes, and synchronize the toggle on application.
  Quick toggles preserve other unfinished edits and never open or close the
  advanced panel. Clear filters resets applied filters and drafts.
- Desktop review details use the visible left list for navigation. Mobile
  details retain Back to list; the redundant desktop back action is hidden.
  Automated verdicts are explicitly labelled Automated outcome.
- Resolve reports — post deleted uses the existing reason, confirmation and
  safe retry controls. Saving refreshes queues, counts and the navigation
  indicator. Mark reviewed explicitly explains that it does not close reports.
- Reporter outcomes and preferences distinguish Post deleted from moderator
  removal. Saved snapshots and audit history remain private and inert.
- Synchronizes generated API models, moderation documentation and help
  knowledge. New messages use the existing en-US fallback in other locales.

## Backend Dependency

The related backend provides `RESOLVE_DELETED_REPORT`, `RESOLVED_DELETED`, and
the deleted/open-report fields and the private case queue/count contract. Release
that backend before this frontend.
No new frontend configuration is required.

## Release Notes

Moderators can work through all outstanding cases from one review workspace,
recognize deleted posts immediately, open live originals, and close reports
after deletion while retaining saved evidence and decision history.
