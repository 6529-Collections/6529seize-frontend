# PR Report: WatchTower review queue and deleted-post reports

PR: https://github.com/6529-Collections/6529seize-frontend/pull/4408
Branch: `agent-prxt/watchtower-deleted-reports` → `main`
Related PR: https://github.com/6529-Collections/6529seize-backend/pull/2214

## Summary

WatchTower opens a Needs review queue with one row per case requiring manual
attention, grouping a post's reports and pending check revisions. It also distinguishes deleted original posts, offers
explicit deleted-report resolution, and links directly to original posts.

## What Changed

- Needs review shows the server-grouped case queue, with source labels, report
  reasons/check outcomes, outstanding requirement counts and a direct Review
  case link. Related pending check revisions remain individually actionable.
- The sidebar dot, tab badge and top summary share the server's unique manual
  review case count. Multiple reports/checks about one post count once. A
  check-only case also triggers attention. The signal refreshes every minute
  while active and after decisions; reading a case does not clear it.
- Cases remain until all their open reports and pending checks are handled.
  Checks and Resolved reports retain history; legacy open-reports links still
  open Needs review. Failed case loads retain prior rows and offer Retry.
- Report cards and check detail show Deleted and Open original post. Links use
  the reported post's own identifiers and trusted relative routes, independently
  of links embedded in evidence. Deleted links explain that the original is no
  longer available; missing or invalid context has a clear fallback.
- Resolve reports — post deleted uses the existing reason, confirmation and
  safe retry controls. Saving refreshes queues, counts and the navigation
  indicator. Mark reviewed explicitly explains that it does not close reports.
- Reporter outcomes and preferences distinguish Post deleted from moderator
  removal. Saved snapshots and audit history remain private and inert.
- Synchronizes generated API models, moderation documentation and help
  knowledge. New messages use the existing en-US fallback in other locales.

## Backend Dependency

The related backend provides `RESOLVE_DELETED_REPORT`, `RESOLVED_DELETED`, and
the deleted/open-report fields and the private case queue/count contract. Release that backend before this frontend.
No new frontend configuration is required.

## Release Notes

Moderators land on all pending reports and checks in Needs review, can open the
original reported post directly, and can close reports after deletion while
retaining saved evidence and decision history.
