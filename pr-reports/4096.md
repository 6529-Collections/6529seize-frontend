# PR Report: Device Farm Stability

PR: https://github.com/6529-Collections/6529seize-frontend/pull/4096
Branch: `agent-prxt/device-farm-stability` -> `main`

## Summary

Harden real-device Safari startup and distinguish infrastructure failures,
app/test failures, incomplete coverage, and recovered runs in mobile QA.

## What Changed

- Safari on iOS 16.4+ launches the target URL through WDA before debugger
  attachment. Both configured iPhones support the launch capability.
- Device-side navigation diagnostics retain offline and startup errors without
  replacing the original failure. Generic errors still require investigation.
- Per-device JSON reports expose selected/executed counts, setup failures,
  and recovery counts. The workflow verifies report completeness against the
  completed Device Farm run's device-job count.
- Web test and command retries are disabled. The existing navigation recovery
  remains visible and cannot qualify as a clean workflow pass. Empty/skipped
  suites, missing evidence, planning/packaging failures, and requested packs
  that cannot run all fail the aggregate report.
- Device pools, cadence, native smoke/fuzz behavior, and all app assertions
  remain intact. No application routes, API contracts, or dependencies change.

## Risks / Follow-Ups

The Safari launch change still needs real-device validation. The acceptance
procedure is ten fresh sequential web runs against the same branch head,
covering both iPhones and all three Android devices with every selected test
executed and no recovery. Keep failed attempts in the evidence record; revise
the fix and restart the streak if the problem recurs. The existing daily
schedule provides longer-term evidence afterward.

Real-device runs were intentionally deferred. Stricter outcome reporting may
surface issues previously hidden by retries or skipped coverage. Older or
unknown iOS versions retain the prior launch path.
