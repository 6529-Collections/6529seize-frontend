# Collect rules as signed records (frontend)

[Frontend PR #5035](https://github.com/6529-Collections/6529seize-frontend/pull/5035) · [Backend PR #2566](https://github.com/6529-Collections/6529seize-backend/pull/2566) · stacked on [#5032](https://github.com/6529-Collections/6529seize-frontend/pull/5032)

## Summary

Saving, pausing and resuming a Collect rule learn to go out as signed records, on the writer and queue #5032 adds for personal settings. Each change is a sealed `collect.rule` item whose body holds the rule's terms and whether it is paused:
- **A new rule:** the item is keyed by the save step's idempotency key, which becomes the rule id in primary.
- **A pause or resume:** the item is keyed by the rule id the list returns, and carries the rule's saved terms field by field.

The device signs them with its existing device key, under its existing grant, so there is no new wallet prompt.

Which write goes out follows the API's mode, as for every personal setting:
- **`legacy`, or the build flag off:** today's route only.
- **`shadow`:** today's route, then the same change as a companion record. That second send is best effort and never shown.
- **`primary`:** the record only. Saved as records, the writers resolve to null and the page reads the list again, as it does today.

Everything else uses today's routes: the rules list, plans, prepare and reconcile.

## Frontend impact

- **For people:** nothing changes until the build has `NEXT_PUBLIC_FEATURE_PERSONAL_RECORDS=true` and the API's mode is `primary`. Then a rule saves, pauses and resumes as a record the device signs.
- **Messages:** the rule card and the save step show what the person can act on:
  - a signed record's refusal: turn on signing, settings paused, or the API's reason;
  - a pending purchase to recover first (409 `RULE_PENDING`), which may name the nonce to replace.

  Anything else keeps today's generic message. The card shows the reason of the action that failed last.
- **Config:** no new flag. It follows `NEXT_PUBLIC_FEATURE_PERSONAL_RECORDS` and the API's mode, as #5032 does.
- **Rollback:**
  - The API's mode going back to `shadow` sends today's route again.
  - A build without the flag removes the code path.

## Frontend deployment

1. Merge #5032 and #2566 first. #2566 is stacked on #2546.
2. Merge this PR. It ships with the personal settings build.

## Tests

- The PR's 7 suites (144 tests) pass. They cover:
  - the three writers (save, pause, resume) in legacy, shadow and primary: today's request, the companion record, or the record only;
  - a rule saved from a checksummed wallet with targets in plan order, signed as the page builds it;
  - the error messages, and the card showing the reason of the last failure;
  - the existing Collect rules suites.
- `tsc`, the Jest and Playwright type checks, ESLint on the changed files, and knip are clean.

## Known limits

- **Old plans after a rebuild:** a plan made before a rebuild answers 404. Saving a rule from it is refused with the API's reason, and the person makes the plan again.
