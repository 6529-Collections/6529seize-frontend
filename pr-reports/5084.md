# PR Report — Isolate homepage artwork in read-only E2E

[PR #5084](https://github.com/6529-Collections/6529seize-frontend/pull/5084)

Related base fix: [PR #5083](https://github.com/6529-Collections/6529seize-frontend/pull/5083) is now merged into main. Its newer synthetic mint, roots mock, stable homepage search setup, and transition-clock correction are retained. This PR closes the remaining iframe-response isolation and Coming Up fixture-readiness gaps, with regression coverage and a shared equivalent sidebar storage guard.

## Problem and evidence

[Production E2E run 45887757451](https://github.com/6529-Collections/6529seize-frontend/actions/runs/45887757451), attempt 2, hit the homepage pack's 15-minute budget and failed the homepage header-search journey. The original search test also reproduced a 60-second timeout against production outside GitHub Actions.

The tests' client API fixtures do not replace the server's initial homepage drop read. A newer server-seeded drop can survive the older fixture, and Coming Up has a second, sandboxed submission iframe renderer. Changing third-party artwork therefore continued executing during unrelated layout and search assertions. Isolating only the marked NFT iframe was insufficient; covering both homepage artwork containers removed the reproduced stalls.

This does not establish a newly introduced application-code regression. The first green-to-red deployed-source comparison changed only roadmap documentation, and earlier runs already contained the server-first homepage implementation.

A separate sidebar-test initializer wrote to `sessionStorage` in every frame, including opaque-origin sandboxed artwork. An isolated browser control reproduced its `SecurityError`; restricting the initializer to the top frame preserved sidebar state without throwing. Inert artwork HTML alone does not fix that initializer, because its sandbox still has an opaque origin.

[Production E2E run 45957233555](https://github.com/6529-Collections/6529seize-frontend/actions/runs/45957233555) checked out the deployed #5083 merge. Eleven packs passed, including search and sidebar coverage; the homepage pack still failed the three-card layout and avatar-density cases on all attempts. An avatar retry still showed live PROOF OF GROWTH artwork, while another snapshot showed unhydrated controls. The three-card test stalled during scroll/stability rather than failing its geometry assertions. These cases began layout/image assertions without waiting for the server-seeded drop to be replaced; their mint RPC was not fixed, and the avatar source mock contained only three JPEG marker bytes, not a decodable image. This evidence identifies fixture gaps, but does not prove every timeout had the same cause.

## Change

- A page-scoped fixture substitutes inert HTML only for GET iframe documents inside current-drop and Coming Up containers.
- Frame lookup/inspection tolerates an iframe being detached during navigation, releases acquired handles, and still propagates unexpected failures while the frame remains attached.
- Homepage layout fixtures and homepage-based search journeys install it before navigation.
- The real application document, renderer elements, API responses, static images, unrelated embeds, and all existing assertions remain intact.
- A synthetic browser regression verifies both artwork containers, repeated installation, fallback navigation, and the unaffected document/API/image/unrelated-script boundaries.
- Sidebar session seeders now share a top-frame-only helper. A separate browser regression reproduces the old exception and checks both preference values with a real sandboxed iframe, without suppressing application page errors.
- The affected Coming Up cases wait for the synthetic current-drop image to be visible and decoded before proceeding, use a deterministic completed mint, and require decoded card images before responsive measurements.
- Avatar probing receives valid PNG bytes instead of a truncated JPEG signature; pixel-density assertions still require the optimized image rather than accepting fallback rendering.
- Saved-sidebar-width cases install iframe isolation before their deliberately gated hydration navigation.
- Sidebar geometry checks wait for the sidebar and asynchronously fetched Update state after a full Notifications navigation; a loading route shell is not evidence that the sidebar/version response has settled.
- Dedicated media packs retain live artwork coverage. No application/runtime, backend, workflow, dependency, or configuration changes.

## Remaining suite scope

The first broader public read-only production check also exposed a Profile Subscriptions panel-readiness failure and a ReMemes loading-grid timeout. Those cases were green in run 45957233555, and both passed twice unchanged on a three-worker recheck. No changes to those specs are included here. They remain load-sensitive coverage rather than proven application regressions; this PR does not claim to make every independent production pack deterministic.

## Risk and operational note

Test-only isolation is not proof that arbitrary third-party artwork is performant. Dedicated media coverage remains responsible for artwork behavior.

Production E2E checks out the exact deployed source. Rerunning an older deployment continues to use its old tests; a future deployed source must include this fix for the ordinary workflow to use it.

Backend services affected: none. Rollback: revert this test-only PR.
