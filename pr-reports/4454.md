# Canonical shared Memes calendar

Calendar math, history, overrides and Athens phase windows now live in a pure
versioned module. Existing UI/API paths remain compatible. Manual claim windows
use the same phase definition.

[Backend #2247](https://github.com/6529-Collections/6529seize-backend/pull/2247)
bundles the identical sources and manifest. See the
[maintenance guide](../shared/memes-calendar/README.md) for the sync/check procedure
and DST behavior. Calendar changes require paired updates and a version bump.

[Automation #4207](https://github.com/6529-Collections/6529seize-frontend/pull/4207)
stacks on this branch. Merge the calendar pair before the automation pair, then
retarget the dependent PR to main. No deployment is included.

Calendar numbering also accounts for future tail overrides in both directions,
including skip/extra conflicts. Sync safely removes obsolete manifest-owned files
and preserves local edits and unrelated files. Regression coverage includes exact
DST durations and sync cleanup.
Overrides retain the existing one-mint-per-eligible-date model; an extra override
does not create another mint on an already eligible date.

Calendar consumers and compatibility re-exports use relative imports so Core's
`@/shared/*` Electron alias cannot intercept them after subtree sync. The shared
module, manifest and calendar behavior are unchanged. A module-resolution contract
checks both frontend and Core-style mappings without altering Core's checkout.
Public calendar UI/API behavior and existing browser coverage remain unchanged.

Next/current/status lookup functions are part of the canonical module, shared by
the existing FE API and BE subscription/Help Bot consumers. API routes and
response shapes stay compatible; the calendar maintenance guide describes the
year-round boundary contract and runtime timezone-data requirement.

Unused standalone override shims and internal-only exports are removed; actual
calendar helper and API consumers remain compatible. Skip-gap coverage confirms
that closing remains fixed on the mint's next day.

Adjacent-extra-day cases cover the live window, close/open gap and transition
back to the regular cadence without extending mint windows.
