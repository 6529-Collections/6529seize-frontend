# PR Report: Fix Manual Staging Public Review Packaging

PR: https://github.com/6529-Collections/6529seize-frontend/pull/3523
Branch: `agent-prxt/fix-manual-staging-public-review` -> `main`

## Summary

Restores public review routes in the manual `1a-staging` deployment path by
packaging the same filtered editorial and review-data artifacts used by the
Release Bus path and supplying the staging discussion destination at runtime.

## What Changed

- Packages the staging-safe public-review bundle into `.next/standalone` before
  starting the server.
- Passes the existing staging-only public-review destination secret through the
  deploy workflow as an encoded handoff and stores it in a protected runtime
  file on the staging host.
- Validates that the destination payload contains the required staging Stream
  review UUID and no production destination.
- Keeps the destination secret out of dependency installation and build
  subprocesses.
- Adds workflow-contract coverage for the manual staging path.

## Frontend Impact

- Routes/views: Restores `/reviews/6529-stream` and its related review routes
  after manual staging deployments.
- Components: Not affected.
- Generated API/client: Not affected.
- User-visible behavior: The Stream public review is available on shared
  staging when `1a-staging` is deployed outside Release Bus.

## Config / Env

The manual staging workflow now consumes the existing
`PUBLIC_REVIEW_DISCUSSION_DESTINATIONS` GitHub Actions secret. No EC2 `.env`
change is required.

## Release Notes

Manual shared-staging deployments now include the filtered Stream review
content and its staging-only discussion destination instead of producing a 404.

## Risks / Follow-Ups

This changes only the legacy/manual staging workflow and standalone startup
wrapper. Release Bus and production deployment paths are unchanged. The
deployment fails closed if the staging destination secret is missing, invalid,
or contains a production destination.
