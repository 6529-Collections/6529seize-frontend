# PR Report: Fix Shared Staging Public Review Publication

PR: https://github.com/6529-Collections/6529seize-frontend/pull/3523
Branch: `agent-prxt/fix-manual-staging-public-review` -> `main`

## Summary

Restores the complete Stream public-review publication contract on shared
staging across both manual `1a-staging` and Release Bus artifacts. Staging
builds now publish the environment-filtered help corpus, the backend can read
the exact Stream review-data namespace, and production remains fail-closed.

## What Changed

- Packages the staging-safe public-review bundle into `.next/standalone` before
  starting the server.
- Builds manual staging with `BASE_ENDPOINT=https://staging.6529.io`, so
  `prebuild` publishes the Stream help records instead of the production-filtered
  corpus.
- Regenerates Release Bus help and agent artifacts only after configuring each
  selected staging or production profile.
- Exempts only `/review-data/6529-stream/` from shared staging access control so
  the backend can retrieve the Stream index, reference manifests, embedded
  indexes, source files, and record shards.
- Keeps `/reviews/...`, neighboring review-data paths, other review IDs, and
  malformed or lookalike Stream paths behind the existing staging gate.
- Uses the existing staging-only GitHub Actions destination secret through the
  same Base64 SSM transport used by Release Bus.
- Decodes the value into a protected runtime file owned by the staging process
  user.
- Validates that the destination payload contains the required staging Stream
  review UUID and no production destination.
- Keeps the destination secret out of dependency installation and build
  subprocesses.
- Adds focused publication, artifact-profile, access-boundary, and behavioral
  runtime-configuration regression coverage.

## Frontend Impact

- Routes/views: Restores `/reviews/6529-stream` and its related review routes
  after manual staging deployments while keeping those pages access-controlled.
- Public artifacts: Makes the published Stream review-data corpus readable by
  the backend on shared staging.
- Components: Not affected.
- Generated API/client: Not affected.
- User-visible behavior: The Stream public review is available on shared
  staging when `1a-staging` is deployed outside Release Bus.

## Config / Env

The manual staging workflow uses the existing
`PUBLIC_REVIEW_DISCUSSION_DESTINATIONS` GitHub Actions secret. No Parameter
Store entry, EC2 AWS CLI installation, instance-profile permission, or EC2
`.env` change is required.

## Risks / Follow-Ups

This changes manual staging publication, Release Bus profile construction, and
the scoped staging artifact-access boundary. Production packaging still rejects
all Stream review/reference/editorial artifacts, production help generation
omits Stream records, and unpublished review versions remain excluded. Manual
staging still fails closed if the GitHub Actions secret is unavailable, invalid, or
contains a production destination.
