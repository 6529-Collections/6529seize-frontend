# Signed posts and encrypted messages across devices

One app grant can authorize signing and encryption. This follow-up adds source-browser approval of fresh Mobile/Core device keys through a private, short-lived connection-share link, so the receiving app can set up without connecting a wallet. Existing target keys and history are preserved; a new device restores past history through encrypted backup. The grant wording is unchanged.

Disconnected-wallet encryption setup now connects then signs automatically, and Connect Device authentication updates resume after connection. Signing-first combined grants are adopted by an already-running encryption engine. The sidebar shield reports this device's proof/encryption states. Narrow/mobile warning buttons use equal-width columns and composer notice text gets the available width.

The shared notification response mapper preserves encrypted DM entries for the bell and All feed. They show a linked sender avatar and handle when available, with a generic fallback for entries without a sender. The row opens the chat, with a setup action on devices without encryption and an exact-message preview when local keys can decrypt it. The API stores no message plaintext. The opt-in `e2ee-staging` journey checks first-message delivery, sender navigation, the locally decrypted preview and chat navigation.

Sign-in retains the explicit Cancel action and Escape cancellation. The redundant top-right close control and version explanation are removed; backdrop clicks remain inert. Prepared app encryption keys are released when no owning profile can adopt them. When device-status features are disabled, the account control describes only the selected account rather than referencing an empty status element. Help guidance qualifies unsigned app posts as posts made without a signing grant.

The setup dialog keeps its actions in view while the body scrolls within the mobile safe area. Refreshing a combined connection clears the old QR while awaiting approval. The receiving app shows both permissions before acceptance. The account controls display wallet connection and device permission status. Preferences shows tabs sized to their labels with an active underline in wide layouts and a two-column grid with a tinted selection in narrow layouts.

The encrypted entry-point sandbox assertion tracks the shorter copy and keeps the narrow-layout checks.

Encrypted chat composition uses the regular desktop emoji popover and mobile slide panel, with the emoji action inside the input and a compact attachment action beside it. Private emoji selections retain inline assets and do not enter usage history. The keyboard shortcut hint moves into the send tooltip. Device Permissions uses “Signed Posts” consistently and shows a combined grant’s expiry once. Ordinary message edit actions expire five minutes after the last update; wave descriptions retain the server’s exemption.

The desktop emoji picker is a native non-modal dialog; opening it does not move it into the browser’s modal top layer. Combined setup retires a superseded signing grant only after its replacement is stored locally. If encryption registration fails afterward, setup reports partial success while the new signing grant remains usable; it does not silently claim both permissions are enabled. Canonical wallet-grant wording is preserved.
