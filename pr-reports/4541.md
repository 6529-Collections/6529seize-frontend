# Signed posts and encrypted messages across devices

One app grant can authorize signing and encryption. This follow-up adds source-browser approval of fresh Mobile/Core device keys through a private, short-lived connection-share link, so the receiving app can set up without connecting a wallet. Existing target keys and history are preserved; a new device restores past history through encrypted backup. The grant wording is unchanged.

Disconnected-wallet encryption setup now connects then signs automatically, and Connect Device authentication updates resume after connection. Signing-first combined grants are adopted by an already-running encryption engine. The sidebar shield reports this device's proof/encryption states. Browser sign-in explains that Version 1 in the wallet refers to the SIWE message version. Narrow/mobile warning buttons use equal-width columns and composer notice text gets the available width.

Encrypted notifications appear even without local keys, with a generic label or a locally decrypted incoming preview. The API stores no message plaintext or sender in these entries.
