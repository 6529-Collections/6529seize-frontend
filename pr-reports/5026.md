# Subscriptions: sign the four subscription changes with the device key (frontend)

[Frontend PR #5026](https://github.com/6529-Collections/6529seize-frontend/pull/5026) · [Backend PR #2547](https://github.com/6529-Collections/6529seize-backend/pull/2547)

## Summary

The web app's side of moving meme subscriptions to 6529 identities. After the backend's switch, the API takes the four subscription changes (mode, edition preference, a card's subscription, a card's count) only as signed records.

With `NEXT_PUBLIC_FEATURE_SIGNED_SUBSCRIPTIONS=true`, each of the four controls signs its change with this browser's device key, under the existing device grant, so there is no wallet prompt. The record goes in the `x-6529-signed-records` header of today's POST, with today's body. One `GET /signed-records/owners` gives the wallet's owner and the finalized height to sign at; an owner answer counts only for the wallet asked about.

Signing never blocks a change before the switch. Without a device grant, or when the owner, the height or the signature can't be had, the change goes unsigned. After the switch, the API's 409 `SIGNED_RECORD_REQUIRED` becomes a toast: "Subscription changes are signed now", with a link to turn on signed posts, or "Couldn't sign this change". A 409 `STALE_SIGNED_RECORD` is signed once more at a fresh height and sent again.

With the flag unset, the requests are today's.

## Frontend impact

- None while the flag is unset.
- With the flag on, before the switch: nothing a person sees changes. The API compares each signed record with today's write.
- After the switch: a person whose browser has no device grant is asked to turn on signed posts before a change saves.
- Five new en-US strings. `openapi.yaml` is synced from the backend: the header and the 400, 409 and 503 answers on the four routes. No generated model is new.

## Deployment

After backend #2547. Deploy with the flag unset; nothing changes. Once #2547 runs side by side (`FEATURE_SUBSCRIPTIONS_SHADOW=true`, opening loaded), set `NEXT_PUBLIC_FEATURE_SIGNED_SUBSCRIPTIONS=true` and redeploy. The backend's switch needs at least 3 signed changes that matched in shadow, with refused ones under 20% of those compared. It is planned for Thu 26 Nov 12:00 UTC, at a real mint.

## Rollback

Before the switch, unset the flag and redeploy. After it, suspend the backend first, because the API then takes only signed changes; then unset the flag.
