# PR Report: Synchronize DM Unread State Across Devices

PR: https://github.com/6529-Collections/6529seize-frontend/pull/3609
Branch: `agent-prxt/dm-unread-sync` -> `main`
Related PRs: [backend PR #1902](https://github.com/6529-Collections/6529seize-backend/pull/1902)

## Summary

Makes direct-message unread state consistent across browsers, devices, profiles, and every frontend surface without recurring polling.

## What Changed

- Added one profile- and conversation-scoped DM unread store with selectors for per-conversation counts, total unread messages, unread conversation count, and any-unread state.
- Replaced aggregate polling and DM-list WebSocket counters with the dedicated authoritative snapshot endpoint and profile-scoped event updates, leaving the legacy count endpoint lightweight for old clients.
- Added immediate optimistic reads with explicit serial targets, authoritative response settlement, and exact failure reconciliation that preserves newer messages.
- Made quick-chat reads use the canonical latest DM serial and request authoritative state even before that conversation is present in the local snapshot.
- Cancels intentionally skipped optimistic sends locally, reserving snapshot reconciliation for actual request failures.
- Added authoritative replacement snapshots that correct equal-version state and remove conversations no longer visible without overwriting newer WebSocket updates.
- Added bounded, coalesced snapshot recovery for authentication and profile changes, WebSocket reconnects, and web or native foreground transitions.
- Retries transient initial snapshot failures within a small fixed budget and rejects stale snapshots or HTTP callbacks across A-to-B-to-A profile activations.
- Coalesces bursts of DM-list invalidations before refreshing the authoritative snapshot.
- Kept API and WebSocket unread counts active until the first complete canonical snapshot arrives for the profile.
- Applies canonical mark-unread responses immediately and uses canonical counts inside open full-chat and single-drop views.
- Preserves unread counts for partial read-through targets while retaining optimistic clearing for reads through the latest known drop.
- Keeps ordinary-wave read requests on the legacy body-less path and requests the richer response only for canonical DM reads.
- Routed desktop navigation, mobile navigation, quick chat, DM lists, conversation rows, and message indicators through the shared authority.
- Preserved ordinary-wave unread behavior and the separate general-notification path.

## Frontend Impact

- Routes/views: Direct messages and global navigation indicators.
- Components: DM conversation lists, quick DM launcher/chat, desktop navigation, and mobile navigation.
- Generated API/client: Adds DM unread snapshot and mark-read response models from backend PR #1902 and requests the dedicated snapshot endpoint.
- User-visible behavior: New DMs and reads synchronize immediately across signed-in sessions without periodic polling.

## Config / Environment

No new frontend configuration or environment variables.

## Release Notes

Direct-message unread badges now stay synchronized across devices, profiles, navigation surfaces, and quick chat in real time.
