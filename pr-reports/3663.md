# PR Report: Separate Page Sharing and Device Connection

PR: https://github.com/6529-Collections/6529seize-frontend/pull/3663
Branch: `agent-prxt/account-share-connect-qr` -> `main`
Related PRs: None

## Summary

Separates desktop page sharing, authenticated device connection, and profile navigation into clear entry points while improving QR camera recognition.

## What Changed

- Added a supported-route desktop Share dialog with a compact always-visible Browser/App QR toggle that remembers its cookie preference, plus icon-only copy, Desktop handoff, X, Farcaster, and conditional system-share controls with rendered tooltips. Browser actions retain the exact full URL; App/Desktop handoffs use the existing `/navigate` deep-link shape.
- Centralized the existing native unsupported-page rules and reused them for desktop without changing native platform-share behavior.
- Moved `Profile` and `Connect Device` into the profile-picture menu, grouped Profile with Logout and both connection actions together, added the supplied device icon, removed the dedicated Profile rail item, and made a single avatar activation open the menu immediately.
- Limited the connection dialog to Mobile and Desktop targets, defaulting to Mobile, with no page-share controls.
- Treated denied/cancelled system-share requests as normal browser outcomes and constrained an unavailable Desktop target back to Mobile.
- Added a two-second full-button success state after copying a link.
- Restored a four-module QR quiet zone, explicit pure-black/pure-white colors, and crisp contained rendering while preserving connection payloads.
- Applied the supplied share-arrow treatment to desktop and native share entry points, with the desktop glyph optically aligned to neighboring sidebar icons.
- Ordered the desktop utility rail as Search, Share, Notifications, then profile.

## Frontend Impact

- Routes/views: Share is hidden on home, Messages, Notifications, and the Messages query view across desktop and native entry points. Waves routes and the Waves query view remain shareable.
- Components: Desktop sidebar, profile menu, page-share dialog, device-connection dialog, native header share icon, and QR rendering.
- Generated API/client: Not affected.
- User-visible behavior: Share, profile navigation, and device connection now have distinct destinations and controls.

## Release Notes

Desktop page sharing now supports copy, QR, X, Farcaster, and system sharing separately from Mobile/Desktop device connection, with improved QR scanning reliability.
