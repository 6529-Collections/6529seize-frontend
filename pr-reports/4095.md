# Canonical coverage and staging search exclusion

PR: [#4095](https://github.com/6529-Collections/6529seize-frontend/pull/4095)

## Final policy

- **ReMemes:** each valid artwork route gets its own canonical, with a lowercase contract and decimal token ID without leading zeros. Supported non-default locales remain; tracking and return-navigation parameters do not.
- **Wallet Checker:** valid addresses remain distinct because they select wallet-specific records. Address case variants consolidate to lowercase. ENS inputs retain their identity until browser resolution; empty/invalid inputs canonicalize to the checker landing page. Unrelated parameters are omitted.
- **NextGen:** use the resolved collection-name slug and retain each resolved tab/subpage path. Overview aliases and unknown views consolidate to the collection root; equivalent supported tab aliases consolidate to one path while the top-trait-sets preview remains distinct from the full trait-sets page. Preserve `traits` and `listed` because they select different artwork, including in preview galleries. Normalize trait order and exact duplicates while retaining API-facing spelling. Sort, rarity display toggles and tracking parameters consolidate to the same filtered gallery. Unknown trait pairs remain conservatively preserved without an additional catalog fetch.

Functional navigation and existing profile, homepage, Memes/Meme Lab and Wave canonical policies remain unchanged. This extends the completed migration; the separate OG endpoint error-handling issue is excluded.

Wallet Checker does not replace its route when hydrating the wallet already supplied by the server or restoring it from browser history. That redundant navigation could replay streamed metadata and leave duplicate canonical and Open Graph URL tags. Submitting or clearing a wallet still navigates to refresh its metadata.

## Staging isolation

Next adds `X-Robots-Tag: noindex` across app-served paths only when the baked `BASE_ENDPOINT` hostname is exactly `staging.6529.io`, as already configured by the staging workflow. This covers staging production builds and `/access`. Request/forwarded hosts cannot opt production into the policy or staging out. The header is constant per deployment, avoiding request-dependent cache variation. Existing production page-specific noindex directives remain.

Authentication and robots.txt crawl permissions stay intact. Blocking crawling would prevent crawlers from seeing noindex; authentication is not relaxed. This covers Next responses, not assets served directly by a separate CDN. No deployment, cache purge, infrastructure or Search Console changes are included.

Sitemap generation remains production-only, using production URLs and data feeds. A missing staging sitemap is not a blocker for this policy; no staging sitemap generation is added.
