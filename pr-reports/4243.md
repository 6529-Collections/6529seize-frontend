# PR Report: Meme collaborator invitations

PR: https://github.com/6529-Collections/6529seize-frontend/pull/4243
Branch: `agent-prxt/meme-collaborator-invitations` → `main`
Related PR: https://github.com/6529-Collections/6529seize-backend/pull/2162

## Summary

Artwork Traits now supports inviting multiple collaborating profiles. Invitees receive a collaboration notification and review the artwork and terms on its detail view before accepting or declining. Acceptance is final; voting starts immediately and public attribution appears only after acceptance.

## What Changed

- Let the original submitter append invitations on existing active Memes Main Stage artwork, including older unmanaged submissions. The author-only control uses backend viewer eligibility, excludes already invited profiles and preserves votes, accepted artists and locked artwork. Invitation creation is restricted to legacy and designated native Main Stage.
- Keep collaborator search behind an Add collaborators disclosure, preserve selections when folded and show a count. Selected artists use compact avatar chips; search shows pending/error states instead of flashing an empty result during debounce or loading.
- Add profile selection to the signed submission payload. Resubmission requires fresh invitations.
- Display private invitation statuses and cancellation for the submitter, and direct acceptance/decline for each invitee. Confirmation is tied to the exact artwork and terms version.
- Announce each invitation's status with its profile handle through a stable status-only live region; action controls stay outside announcements.
- Show accepted collaborator links across artwork details, leaderboards, winners, profiles and home next-mint cards, including native competition detail views.
- Preserve empty original artist values during drop mapping. Artwork details load invitation state only when the managed original-credit marker (including an empty string) or accepted collaborators are present. Ordinary drops avoid the extra request; restricted artwork does not mount invitation controls.
- Keep all Craft artwork and credit fields editable by admins, including Artist, SEIZE Artist Profile and Collab. Saved admin values determine final Arweave metadata without invitation checks.
- Synchronize OpenAPI/generated models; update localized messages, submission/Forge documentation and help knowledge.

## Frontend Impact

The existing Notifications inbox (including its Invites filter) and artwork detail views host the invitation flow. No new page is added. Profile active/won lists consume backend accepted-attribution data. Pending names remain private; the original author retains submission ownership and editing permissions.

## Release Notes

Claims Builder uses collaborators who accepted before selection for initial mint credits. Unanswered invitations close at selection. Acceptance remains final for submission attribution; admins may edit final mint metadata in Craft. Manually crediting an unaccepted artist does not accept their invitation or change accepted-submission profile lists.

## Risks / Follow-Ups

Roll out the companion backend schema, workers and API before this frontend. Retain consent records and selection handling for collaborations already in flight if reverting the UI. Browser E2E was not executed in this no-server, no-deployment task; state/consent and payload paths are covered at lower layers.

Collaboration controls, statuses, notifications and consent copy currently use the en-US dictionary as the fallback in en-GB, fr-FR, es-ES and de-DE. Invitees in those locales see English, including the final-acceptance and confirmation text. The frontend localization maintainers own translation follow-up; prioritize reviewed consent translations before expanding localized collaboration guidance.

Screen-reader announcement scope is verified through DOM/status-transition coverage. VoiceOver/NVDA speech output was not checked; the frontend accessibility maintainers should smoke-check announcements on deployed artwork details.

Existing browser notification and native-competition packs were inspected for affected labels and fixture contracts. The new addition flow reuses the profile picker and authenticated POST helpers; focused component tests cover selection, existing-profile exclusions, author visibility and the append payload. No browser expectation was weakened. Browser execution remains deferred under the no-local-server constraint.

The full local production build reaches Next configuration loading but cannot continue without the required build environment (including API, allowlist and base endpoint settings). CI must supply the full production-build evidence for this extension.


The collaborator picker follows the existing Quick Tags chip pattern with identity avatars, compact handles and separate accessible removal controls. Search alignment is scoped to this picker; the shared identity search now distinguishes debounce/fetch/error from successful empty results and suppresses stale-query options. The native drop loader uses the public Participatory enum because the API normalizes native COMPETITION entries to that value; viewer invite capability is author-scoped on the backend and the panel also defends against an empty nonauthor section. Appending pending invitations updates the private invitation cache only: accepted public credits are unchanged until acceptance, whose existing invalidation remains in place.

Existing notification, drop-editing and nomination selectors remain unchanged. This browser case was added but not executed because local dev servers and deployments are not authorized; rendered alignment and narrow-screen screenshots still need that execution evidence. Component coverage exercises the real debounce rather than the shared no-op debounce mock.
