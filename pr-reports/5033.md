# Profile sites on the chain: the browser uploads a site's files (frontend)

[Frontend PR #5033](https://github.com/6529-Collections/6529seize-frontend/pull/5033) · [Backend PR #2568](https://github.com/6529-Collections/6529seize-backend/pull/2568) · builds on #5025; merges after #5025 and the backend PR

## Summary

With profile sites on the 6529 chain, the backend no longer puts a site's two files in the gateway's document store: publish returns them, and the person's browser uploads them. After a chain publish, the builder checks the files are the ones the person signed (the signed package hash's content core and the recorded publication record) and checks each against its CID. It uploads them through the profile tools' writer, then signs the PROFILE_REPLACE that names exactly those CIDs. A missing or mismatched file, or a refused upload, stops before anything is signed, in the writer's own words for a refusal.

Nothing changes until the backend's chain flag is on, and it stays off until this PR and the backend half are both deployed.

## Frontend impact

- None while the backend flag is off.
- Once it is on, a publish makes three uploads from the person's browser: the two files, then the next ProfileDoc version, which the writer already uploads. Rollback and unpublish upload only the ProfileDoc.
- The shared `profile-doc-writer.ts` gains `uploadDocuments` and two error codes, `upload_too_large` and `upload_refused`. It's byte for byte the interface the identity frontend agreed.
- New strings in all five locales. `openapi.yaml` and the models are synced from the backend half.

## Deployment

Deploy with or after the backend half, and with the identity frontend's writer that implements `uploadDocuments`, before the backend's `FEATURE_PROFILE_CMS_CHAIN_POINTER` goes on.

**Rollback:** the backend flag off; this code then never runs.

## Asks

- **The chain identity profile tools** (identity frontend): copy the final `profile-doc-writer.ts` and implement `uploadDocuments`:
  - one file at a time, with each CID passed to `?cid=` unchanged;
  - stop at the first refusal;
  - the agreed words for each cause.

## Risks and follow-ups

- A refused upload keeps the signed request. A retry publishes again, gets the recorded files and resumes, since stored files answer 200.
- **Tests:**
  - the upload before the PROFILE_REPLACE;
  - a file that doesn't match its CID;
  - another package hash, core or record, or an answer without its files, uploading and signing nothing;
  - a refusal, and a retry after it;
  - the decoder;
  - fixed CID vectors.

  tsc, the typecheck ratchet, the changed-file lint gate and knip are clean.
