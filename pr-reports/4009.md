# PR Report: Upcoming subscription allocation status

PR: [#4009](https://github.com/6529-Collections/6529seize-frontend/pull/4009)

Related PR: [Backend #2048](https://github.com/6529-Collections/6529seize-backend/pull/2048)

## Summary

The first subscribed row in Profile → Subscriptions → Upcoming Drops shows
`No subscription allocation` when distribution is published and the finalized
subscription list has no record for that profile. Assigned phases retain their
position details, while a phase-less finalized record remains pending.

## What Changed

- Keep the message hidden for unsubscribed cards, unpublished distributions,
  phase-less finalized subscriptions, loading, and failed requests. A missing
  final-subscription record (404) is distinguished from a failed lookup.
- Check publication using the viewed profile, not the connected wallet's
  eligibility. Only the card-wide publication flag is used.
- Refresh final subscription and publication data once per minute while visible.
- Add translations, user documentation, and help corpus facts covering this
  state and the companion backend cutoff correction.
- Announce the message through a native output element. Existing English-only
  phase metadata and controls remain documented localization debt.

## Rollout Dependency

Deploy backend #2048 before this frontend so mint-day status no longer infers
subscription from Automatic mode enabled after cutoff. API response shapes and
generated models are unchanged; no new settings are required.

The publication signal indicates normalized distribution exists. A finalized
subscription row without a phase is treated as pending because later phase or
Public processing can still assign it. The message does not explain why a
profile was absent from the finalized subscription list.

## Release Notes

Upcoming Drops explicitly identifies a subscribed card with no allocation once
distribution is published, while retaining phase and position for assigned cards.
