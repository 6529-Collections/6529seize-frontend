## Summary
Guided Setup plans reciprocal links for two to four wallets, orders existing members first and supports self-batched signing or managers signing one link per transaction. It now gets fourth-wallet consent and signing-open times from backend settings rather than a frontend launch-date constant.

## What Changed
- The OpenAPI contract and generated models include the backend consolidation policy.
- Four-wallet steps, link freshness and displayed dates use the selected environment’s cutoff. Signing opens ten minutes later, as supplied by the backend.
- Missing, invalid or failed settings keep four-wallet signing unavailable and provide a retry. Two/three-wallet plans continue. A changed cutoff discards the old planning baseline and re-evaluates links.
- User documentation and help knowledge explain the environment timing. The unpublished same-origin documentation package identifies its October 15 date as the production launch and has regenerated hashes. Its prior published bundle is untouched.

## Config / Env
No frontend cutoff variable is added. Deploy the backend settings contract and configure the backend’s `CONSOLIDATION_FOUR_WALLET_ACTIVATION_AT` before this client. Refresh existing sessions after a backend policy change. The parent of the collector-guide and Safe Collecting PRs must be merged into those branches before rollout.
