## Summary
Guided Setup plans reciprocal links for two to four wallets, orders existing members first and supports self-batched signing or managers signing one link per transaction. It now gets fourth-wallet consent and signing-open times from backend settings rather than frontend copies of launch dates or wallet limits.

## What Changed
- The OpenAPI contract and generated models include backend `max_wallets` and `ungated_max_wallets`. Wallet validation, row limits, prefill, profile entry points and consent checks consume that shared policy.
- Four-wallet steps, link freshness and displayed dates use the selected environment’s cutoff. Signing opens ten minutes later, as supplied by the backend.
- Missing/invalid wallet limits pause guided signing without inventing a frontend maximum. Valid limits still allow two/three-wallet plans when only the cutoff is unavailable. Four-wallet signing requires the complete policy; retry reloads the existing settings request. A changed cutoff or limit discards the old planning baseline.
- User documentation and help knowledge explain the environment timing. The unpublished same-origin documentation package identifies its October 15 date as the production launch and has regenerated hashes. Its prior published bundle is untouched.
- Four-wallet regressions cover all profile wallet rows, the three-to-four add-wallet boundary, Wallet Checker’s complete group and twelve directions from every member, shared address expansion, fourth-wallet selection, and consolidated collection/TDH statistics with and without a fourth-wallet custody filter.
- The profile wallet count is right-aligned as a separate item on its heading row. This leaves the broader Addresses/ID Statements layout and tooltip work to FE #4290; preserve its heading and controls when combining the branches.

## Config / Env
No frontend cutoff or limit variable is added. Both limits remain fixed backend constants, not new secrets or support for arbitrary group sizes. Deploy the backend settings contract and configure the backend’s `CONSOLIDATION_FOUR_WALLET_ACTIVATION_AT` before this client. Refresh existing sessions after a backend policy change. Guided Setup, the collector guide and Safe Collecting now ship together in combined frontend #4219.

## Risks / Follow-Ups
