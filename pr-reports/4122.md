# Active votes and wave sidebar navigation

[PR #4122](https://github.com/6529-Collections/6529seize-frontend/pull/4122) makes active TDH voting discoverable and removes the need to scroll through pinned waves before reaching other collections.

Active Votes and Worth Checking Out are independent collapsible sections, in that order. Each compact header contains a separate View all link before the chevron, available even when collapsed; the link navigates without toggling the section. Descriptions use smaller text and tighter spacing. Active Votes uses a scrollable two-row window with compact 56px rows, named votes, deadline labels, score shields, a thin scrollbar and a bottom fade when more rows remain below. Scrolling near the end loads another page; a keyboard-accessible Load more button provides a fallback. Failed pages retain existing rows and can be retried. Empty, loading and initial-error states remain compact. Worth Checking Out has up to six avatar previews and its own natural height. Recommendation shields retain the original bottom-right overlap, with room reserved at the strip edge. Each section saves its collapse preference in local storage and defaults to expanded. Preferences are shared across profiles on the same browser/device, including guest collapse choices; obsolete shared tab preferences are ignored. Collapsed content is inert and hidden from assistive technology, and reveal/chevron motion respects reduced motion.

The plain Waves heading has right-aligned feed, discover and create icon buttons on desktop; the mobile list has feed and discover, with create retained in the app top bar. These replace the Profile Waves Feed row on desktop and the separate mobile feed card. Mobile uses Waves rather than All Waves as its heading, and opens the explicit profile-feed route. App and mobile-browser search controls and vote fades match their surrounding surface; the announcement divider adds no extra gap above the first discovery header. The tooltip is “Waves Feed”, with blue icon feedback on active, hover and focus states. The header actions share subtle dark backgrounds, desktop tooltips and larger touch targets. All / Pinned / Joined are compact peer controls above one list; signed-out visitors see All Waves. Inline search spans accessible non-DM waves independently of the collection and preserves its session query, pagination and scroll state. Approximate matching and relevance changes are outside this PR.

Announcements uses a compact row while retaining its megaphone, timestamp, unread state and score shield. Unread/pin controls, subwaves and DM navigation are preserved. Direct user scrolling cancels pending restoration. Collapsed-rail pagination remains enabled with a saved Pinned preference, and the rail is labelled as All to match its contents without overwriting that preference. The sidebar and full discovery page share the existing 20-item paginated query; periodic refresh includes pages loaded by either surface. The full discovery page retains its tab semantics and keyboard navigation.

The search input stays disabled in the initial server preview until its handlers and saved query are ready. This prevents a first query typed during page startup from being discarded. The sidebar browser contract waits for the input to become interactive, asserts that the first query survives, and exercises the independent disclosures rather than the retired shared tabs.

Search keeps its scope accessible without a duplicate visible heading, suppresses the browser's extra clear icon, and replaces the magnifier with a small spinner while a searchable query is waiting or fetching. The full discovery page uses compact tabs with straight active indicators. Both views use the Active Votes heading typography (24px semibold) and the same 16px gap below the tabs; the home-page discovery heading is unchanged. Signed-out visitors see “Active discussions” there and “Highly rated waves.” in the sidebar; personalized following copy appears only for authenticated personal viewers.

Deploy the API from [backend PR #2126](https://github.com/6529-Collections/6529seize-backend/pull/2126) first. Active-vote visibility does not guarantee voting eligibility. DMs and their subwaves are excluded even when readable. Product docs and the help corpus describe the independent disclosures and scrollable list.

New discovery/search strings use the existing en-US fallback in en-GB/fr-FR/es-ES/de-DE. Frontend wave-navigation maintainers own the remaining translations and expanded-label verification. Full application navigation and scrolling have not been exercised locally because no local server was authorized; focused browser evidence uses the real components with fixture data.
