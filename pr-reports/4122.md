# Active votes and wave sidebar navigation

[PR #4122](https://github.com/6529-Collections/6529seize-frontend/pull/4122) makes active TDH voting discoverable and removes the need to scroll through pinned waves before reaching other collections.

Active Votes and Worth a Look are independent collapsible sections, in that order. Each keeps its description and view-all link outside its content list. Active Votes uses a scrollable two-row window with named votes, deadline labels, a thin scrollbar and a bottom fade when more rows remain below. Scrolling near the end loads another page; a keyboard-accessible Load more button provides a fallback. Failed pages retain existing rows and can be retried. Empty, loading and initial-error states remain compact. Worth a Look has up to six avatar previews and its own natural height. Each section saves its collapse preference in local storage and defaults to expanded; obsolete shared tab preferences are ignored. Collapsed content is inert and hidden from assistive technology, and reveal/chevron motion respects reduced motion.

The Waves heading and feed icon replace the Profile Waves Feed row. The tooltip is “Waves Feed”, with blue icon feedback on active, hover and focus states. The smaller Create wave button preserves its colours, tooltip and touch target. All / Pinned / Joined are compact peer controls above one list; signed-out visitors see All Waves. Inline search spans accessible non-DM waves independently of the collection and preserves its session query, pagination and scroll state. Approximate matching and relevance changes are outside this PR.

Announcements, unread/pin controls, subwaves and DM navigation are preserved. Direct user scrolling cancels pending restoration. Collapsed-rail pagination remains enabled with a saved Pinned preference. The sidebar and full discovery page share the existing 20-item paginated query; periodic refresh includes pages loaded by either surface. The full discovery page retains its tab semantics and keyboard navigation.

The search input stays disabled in the initial server preview until its handlers and saved query are ready. This prevents a first query typed during page startup from being discarded. The sidebar browser contract waits for the input to become interactive, asserts that the first query survives, and exercises the independent disclosures rather than the retired shared tabs.

Search keeps its scope accessible without a duplicate visible heading, suppresses the browser's extra clear icon, and replaces the magnifier with a small spinner while a searchable query is waiting or fetching. The full discovery page uses compact tabs with straight active indicators. Signed-out visitors see “Active discussions” there and “Highly rated waves.” in the sidebar; personalized following copy appears only for authenticated personal viewers.

Deploy the API from [backend PR #2126](https://github.com/6529-Collections/6529seize-backend/pull/2126) first. Active-vote visibility does not guarantee voting eligibility. DMs and their subwaves are excluded even when readable. Product docs and the help corpus describe the independent disclosures and scrollable list.

New discovery/search strings use the existing en-US fallback in en-GB/fr-FR/es-ES/de-DE. Frontend wave-navigation maintainers own the remaining translations and expanded-label verification. Full application navigation and scrolling have not been exercised locally because no local server was authorized; focused browser evidence uses the real components with fixture data.
