# Active votes and wave sidebar navigation

[PR #4122](https://github.com/6529-Collections/6529seize-frontend/pull/4122) makes active TDH voting discoverable and removes the need to scroll through pinned waves before reaching other collections.

Worth Checking Out and Active Votes are independent collapsible sections, in that order. Each compact header contains a separate View all link before the chevron, available even when collapsed; the link navigates without toggling the section. Descriptions use smaller text and tighter spacing. Active Votes uses a scrollable three-row window with compact 48px rows, named votes, deadline labels, score shields, a thin scrollbar and a bottom fade when more rows remain below. Scrolling near the end loads another page; a keyboard-accessible Load more button provides a fallback. Failed pages retain existing rows and can be retried. Empty, loading and initial-error states remain compact. Worth Checking Out has up to six avatar previews and its own natural height. Recommendation shields retain the original bottom-right overlap, with room reserved at the strip edge. Each section saves its collapse preference in local storage and defaults to expanded. Preferences are shared across profiles on the same browser/device, including guest collapse choices; obsolete shared tab preferences are ignored. Collapsed content is inert and hidden from assistive technology, and reveal/chevron motion respects reduced motion.

The plain Waves heading has right-aligned feed and create icon buttons on desktop; the mobile list has feed only, with create retained in the app top bar. These replace the Profile Waves Feed row on desktop and the separate mobile feed card. Mobile uses Waves rather than All Waves as its heading, and opens the explicit profile-feed route. App and mobile-browser search controls and vote fades match their surrounding surface; the announcement divider adds no extra gap above the first discovery header. The tooltip is “Profile Waves Feed”, with blue icon feedback on active, hover and focus states. The feed action has a charcoal background and subtle border; create has a white background and dark plus. Both retain desktop tooltips and larger touch targets. Discover Waves moves to a labeled compass link in the feed content header. All / Pinned / Joined are compact peer controls above one list; signed-out visitors use the All collection without a duplicate visible heading. Inline search spans accessible non-DM waves independently of the collection and retains its query during in-page navigation, pagination and scroll state; refresh clears the query and restores the last selected collection. Approximate matching and relevance changes are outside this PR.

Announcements uses a compact row while retaining its megaphone, timestamp, unread state and score shield. Unread/pin controls, subwaves and DM navigation are preserved. Direct user scrolling cancels pending restoration. Collapsed-rail pagination remains enabled with a saved Pinned preference, and the rail is labelled as All to match its contents without overwriting that preference. The sidebar and full discovery page share the existing 20-item paginated query; periodic refresh includes pages loaded by either surface. The full discovery page retains its tab semantics and keyboard navigation.

The search toggle stays disabled in the initial server preview until its handlers are ready. This prevents a first query typed during page startup from being discarded. The sidebar browser contract waits for the input to become interactive, asserts that the first query survives, and exercises the independent disclosures rather than the retired shared tabs.

Search keeps its scope accessible without a duplicate visible heading, suppresses the browser's extra clear icon, and replaces the magnifier with a small spinner while a searchable query is waiting or fetching. The full discovery page uses compact tabs with straight active indicators. Both views use the Active Votes heading typography (24px semibold) and the same 16px gap below the tabs; the home-page discovery heading is unchanged. Signed-out visitors see “Active discussions” there and “Highly rated waves.” in the sidebar; personalized following copy appears only for authenticated personal viewers.

Deploy the API from [backend PR #2126](https://github.com/6529-Collections/6529seize-backend/pull/2126) first. Active-vote visibility does not guarantee voting eligibility. DMs and their subwaves are excluded even when readable. Product docs and the help corpus describe the independent disclosures and scrollable list.

New discovery/search strings use the existing en-US fallback in en-GB/fr-FR/es-ES/de-DE. Frontend wave-navigation maintainers own the remaining translations and expanded-label verification. Full application navigation and scrolling have not been exercised locally because no local server was authorized; focused browser evidence uses the real components with fixture data.

Worth Checking Out precedes Active Votes in both discovery surfaces; recommendations remain the default route. Voting dates use muted metadata text while counts and navigation links retain blue accents.

The primary navigation rail keeps its single-chevron toggle entirely inside the sidebar’s right edge at the vertical center, 20px wide in both states. The logo matches main’s 40px size. Sidebar hover or keyboard focus reveals the toggle, while touch layouts keep it visible. Collapsed-rail submenu flyouts temporarily hide the expand handle until the flyout closes. The logo retains its original horizontal center and uses main’s 2% hover scale-up with a visible warm glow across the full logo hover target; reduced motion disables scaling. The handle uses main’s iron-800 surface, brightening to iron-700 on hover; the single chevron stays light. Its curved 1px iron-800 outline matches the sidebar divider and meets its center without a second straight edge. The outline stays unchanged on hover. Shape-following shadows preserve the curved handle silhouette. Its flat edge meets the sidebar boundary in both states. Expandable navigation rows inset their chevrons by an additional 8px, consistently across primary and nested groups. On desktop, the feed title and Discover Waves link align with the Waves sidebar heading by reducing the feed’s top padding; mobile feed spacing is preserved.

A synchronous startup script reads the existing session preference before paint. Saved expanded desktop layouts reserve the sidebar and page offset immediately, then reveal sidebar content when React restores the same state. This does not delay page content, change persistence, or override narrow-screen/native layouts. Invalid or unavailable storage retains the collapsed default.

The collection content area below the tabs shows a small centered spinner while its waves are loading, including the separate pinned-waves request. Existing rows in the selected collection refresh silently; the spinner appears only while an empty collection loads. Tab labels stay fixed. Empty collection feedback waits for that loading to finish.

Fallback video autoplay ignores `AbortError` cancellations caused by pausing, source changes, or unloading. Other playback rejections remain visible as warnings. Playback behavior is unchanged.

Active Votes on discovery uses a compact variant of the Worth Checking Out cards, with a narrow rectangular artwork panel on the left with cover imagery, a single-line ellipsized title, smaller blue voting end or next decision, and a single-line description. Initial loading uses matching compact shimmer cards instead of visible loading text. Existing server deadline ordering and pagination remain unchanged; no sorting controls or backend changes are introduced. The signed-out/auth-loading “All Waves” label below sidebar search is removed to avoid a refresh flash.

Sidebar search is opened through a separate magnifier beside All / Pinned / Joined. Opening replaces the controls with a focused search field; closing or Escape clears the query and restores the selected collection. The breakpoint browser contract scopes its plain-heading assertion to the Waves header, preserving unrelated main-navigation links.

Discovery defaults to Worth Checking Out when router search parameters are unavailable and can still navigate between its tabs.
