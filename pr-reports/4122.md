# Active votes and wave sidebar navigation

[PR #4122](https://github.com/6529-Collections/6529seize-frontend/pull/4122) makes active TDH voting discoverable and removes the need to scroll through pinned waves before reaching other collections.

Active Votes and Worth a Look share a collapsible discovery section. The copy is “Community decisions powered by TDH.” and “Highly rated waves you don’t follow.” Both panels share a grid cell to retain equal height when switching, including empty, loading and error states. Short reveal/fade transitions and a rotating chevron respect reduced motion. Inactive and collapsed content is inert, excluded from sequential keyboard focus and hidden from assistive technology. The header has two equal-width tabs with centred labels and a separate disclosure control. Loading, error and empty status rows share the same minimum height and alignment, keeping text and the footer steady when retry appears. Compact, single-line labels use a straight active underline, and the chevron points down when expanded or right when collapsed. Search and the full-width All/Pinned/Joined segmented control use reduced height and padding. The Waves heading and a small feed icon replace the separate Profile Waves Feed row. The link clears the selected desktop wave or opens the explicit mobile-web feed, retains normal modified-click navigation, and shows “Waves Feed” on hover/focus. Its icon turns blue when active or hovered/focused. The collapsed rail keeps its icon-only feed shortcut. Empty Active Votes shows a clear message and a button to browse recommendations while retaining the zero-count tab. The active count stays visible, named previews show voting deadlines or next decisions, and the view-all links open the matching discovery view. All, Pinned and Joined become peer controls above one wave list; signed-out visitors see All Waves.

Inline wave search spans accessible non-DM waves independently of the selected collection. It shows creator and pinned/joined status, supports pagination, retains the query when opening a result and restores the collection on clearing. Existing name matching remains unchanged; approximate search and relevance ranking are outside this PR.

The redesign retains announcements, unread/pin controls, subwave navigation, recommendation score links and DM behavior. Discovery preferences and collection selection persist locally across visits in this browser. Viewer-specific search queries remain session-only. Worth a Look shows up to six spaced previews with fewer on narrow screens. The first and last circles in a full strip align with the content edges; score badges stay inside the avatar’s horizontal bounds. The smaller plus button preserves its original colours and exposes a Create wave tooltip on hover/focus. Collection scroll restoration is owned by sidebar navigation, so virtual-list resets do not compete with tab switches. Search keeps its scroll position through pagination and refreshes and remembers the reachable position when the result list shrinks. The obsolete stacked-list filter and its unused exports are removed.

Deploy the API from [backend PR #2126](https://github.com/6529-Collections/6529seize-backend/pull/2126) first. Visibility of an active vote does not guarantee voting eligibility. New UI messages use the existing English locale fallback.

Browser coverage was updated for the new discovery and search flow. An isolated render of the actual sidebar controls checked desktop and 320px touch layouts with fixture data and placeholder avatars, including stable tab heights for populated, empty, loading and error states, complete collapse, keyboard selection, icon hover and reduced motion. Full application navigation, scroll and keyboard verification remains outstanding because no local server was authorized.

Search feedback uses a persistent live status, collection selection uses a filled segment and heavier text, and discovery controls identify their panel. Scroll restoration retains a saved offset while asynchronously loaded rows are too short to reach it, but direct wheel, touch, pointer or keyboard interaction cancels the pending restoration so later rows cannot move the user unexpectedly. Sidebar previews intentionally use a separate two-row query from the paginated discovery view: loading more pages must not expand the sidebar's periodic refresh workload.

Localization fallback debt: SidebarDiscovery, SidebarWaveNavigation, ActiveWaveVotes, ActiveWaveVoteRow, DiscoverWaveExplorer and the sidebar Create wave button use source-locale `waves.discovery.*` and new `waves.sidebar.*` messages. Missing en-GB/fr-FR/es-ES/de-DE translations render en-US, so those visitors see English discovery/search copy. Owner: frontend wave-navigation maintainers; follow-up: translate these keys and verify expanded labels in the sidebar before removing fallback debt. Joined/collection empty states and pinned labels resolve the browser locale.

Collapsed-rail pagination remains enabled regardless of the saved Pinned collection, and the expanded list’s accessible name follows the rendered collection. Both discovery switchers expose labelled tab panels and arrow/Home/End keyboard navigation. The generated agent glossary stays synchronized with the help corpus.
