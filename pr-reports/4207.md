## Summary

Defines operator-facing requirements for unattended Drop Forge launches and EMMA
recovery. This is a requirements analysis only; no frontend behavior changes.
Full analysis: [frontend requirements](../ops/workstreams/drop-forge-auto-launch/requirements.md).

## What Changed

- Defined proposed launch configuration/review/arming, progress, pause/resume/
  cancel, and coordination with manual transactions.
- Specified global `@dropforgers6529` mention support with backend-owned
  resolution of the manually supplied recipient profile IDs.
- Outlined EMMA preparation/finalization status and timeout recovery with
  downloads of completed results.
- Recorded contract dependencies, acceptance scenarios, and future coverage.

## Frontend Impact

No routes, components, generated models, or runtime configuration change. Future
work touches Drop Forge launch, EMMA review/export, and global mention surfaces
after backend contracts and operational policies are settled.

## Risks / Follow-Ups

Backend timeout diagnosis and durable execution/status contracts precede UI
implementation. Manual takeover, missed-window UX, and group-mention invocation
permissions remain open. User docs and help knowledge must describe the feature
only when its runtime behavior is implemented.
