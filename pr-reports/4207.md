# Drop Forge operator controls and EMMA processing

PR: [Frontend #4207](https://github.com/6529-Collections/6529seize-frontend/pull/4207)
Companion: [Backend #2143](https://github.com/6529-Collections/6529seize-backend/pull/2143)

EMMA uses one Process and Finalize action with durable processing, completed and
failure states. Refresh discovers the current job. Subscription CSV downloads
read the completed job's paginated lists rather than repeat preparation writes.
Normal phase/component exports and existing allocation/photo controls remain.

Craft adds Launch after publication and Update Claim after republished metadata
changes. Launch queues initialization immediately using the backend's fixed mint
calendar. Loaders reflect backend work, blocked errors remain visible, and dirty
or unpublished edits cannot submit. Metadata updates preserve mint configuration
and completed airdrops. Edition/distribution changes need separate review.

The existing Launch page shows durable action progress and transaction links.
Manual writes acquire a backend lease before prompting the wallet; accepted
hashes carry the action category and persist locally until submitted successfully,
including across refresh. Confirmed evidence credits only remaining allocations.
Unknown wallet outcomes keep automation paused for explicit hash reconciliation
or safe cancellation. Automation updates the existing completed-category flags.

Generated API contracts match the companion backend. @dropforgers6529 renders
as a reserved global mention; recipient IDs are resolved by the backend. User
guidance and help knowledge describe processing, immediate launch, metadata
updates, phase timing and manual recovery.

Automation/preparation remain default-disabled. Wave/profile IDs, credentials,
KMS key, wallet funding and on-chain admin grants are manual deployment inputs.
Live KMS/chain/wave execution and end-to-end browser flows were not exercised;
no local development server was started. No deployment or main merge is included.

Completed-list access requires the three current phase IDs; missing or stale
job evidence stays unavailable. Manual hash persistence is tied to the write's
local attempt and lease, and cancellation clears only that attempt. Callback
identity changes cannot retrigger the confirmed-work refresh. Null leases remain
an explicit legacy/unmanaged permission, while managed conflicts reject BEGIN.
