# PR Report: Wave drop structured-data publication dates

PR: https://github.com/6529-Collections/6529seize-frontend/pull/4137

Related PR: [Backend #2129](https://github.com/6529-Collections/6529seize-backend/pull/2129)

## Summary

Public Wave drop structured data now uses the genuine original publication timestamp for chats and submissions. The reported “gm meme” chat was published at `2026-09-28T22:22:35.501Z`; its old metadata exposed no publication date because `submitted_at` is submission-only.

## What Changed

- Format `drop.created_at` as ISO 8601 `datePublished`; never substitute current, winner or wave dates.
- Replace `articleBody` with the supported `text` property; classify video media separately from images and omit invented fallback headlines.
- Require a usable publication date, author name and text/image/video before emitting a post node. Keep the wave graph when a post is incomplete or unavailable.
- Regenerate models from the exact backend contract. Existing route access, private-content and moderation behavior is unchanged.

## Backend Deployment

Planned, not deployed by request: deploy the related backend `api` update before the frontend. Older metadata lacks `created_at`; until the API is updated, the frontend deliberately omits incomplete post nodes.

## Risks / Follow-Ups

After the separately authorized rollout, recrawl and validate the affected Search Console items. This repair addresses rich-result eligibility data; it does not establish that normal indexing was blocked or guarantee a rich result. No Search Console changes are part of this task.
