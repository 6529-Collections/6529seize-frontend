# Sidebar, account menu, and auth loading stability

PR: [#4061](https://github.com/6529-Collections/6529seize-frontend/pull/4061)

## Summary

Keep sidebar utilities and the account control stationary as wallet restoration,
profile images, notifications, and Update availability resolve. Check artwork
documentation access independently of opening the account menu, and reveal its
item as soon as access is known. Protected pages wait for wallet/profile restoration before deciding whether
to show content, connect-wallet, profile-setup, or access-denied states. Existing
server rendering and public SEO content remain intact.

## Changes

- Separate scrollable primary navigation, Search/Share/Update, and bottom account
  actions. Conditional Drop Forge and WatchTower stay in the navigation section.
- Anchor the account control at the bottom with Notifications immediately above.
  Update follows Share in the fixed-height middle section, or sits directly below
  Search on routes without Share. Unused space stays below the visible controls;
  Notifications cannot move them. No empty notifications row appears for signed-out
  visitors.
- Reveal sidebar controls and labels with a 125ms fade and subtle scale, including
  conditionally visible Notifications, Update, Drop Forge, and WatchTower. Use a
  simple fade for account/avatar states. Respect reduced motion and avoid
  restarting the animation on ordinary rerenders.
- Use a fixed 40px account frame with a PFP, shimmer, or centered 24px default
  symbol. Signed-out frames use a neutral ring; connected frames retain their
  existing status colors. Missing, broken, and stalled
  images fall back to the icon; failed profile requests expose a retry action.
  An empty successful result links to profile setup. Screen readers receive
  account identity and retry feedback. A timed-out avatar stays on its fallback
  until the account or image URL changes, avoiding another delayed image swap.
- Keep artwork access subscribed while the account UI is mounted. Opening the
  menu does not restart the request. Late positive results appear immediately
  in an open menu, while revoked access disappears immediately. Account/proxy changes
  are isolated and logout drops the previous access result. No persistent cache
  is added.
- Render local/staging environment badges from the request origin in the initial
  HTML and hydration pass, including local ports. Production still omits the badge.
  This presentation-only value does not alter SEO metadata or auth behavior.
- Treat unresolved authentication as loading across Messages, Create Wave, artwork
  documentation, WatchTower, Orders, EMMA, the CMS builder, and direct-message
  widgets. Preserve public wave content while its composer resolves access.
- Wait for live signer restoration in delegation actions and collection panels,
  NextGen Manager, EMMA sign-in, Rememe submission, wallet balance, and mint/burn
  controls.
  NextGen Manager also waits for its initial permission reads. Drop Forge handles
  in-progress connections as loading. EMMA derives its state directly rather than
  showing a disconnected state on every mount.
- Keep resolved documentation/CMS editors mounted during profile refreshes; no
  account caching or artificial delay is added.
- Update navigation/account documentation and the help corpus.

## Risks and follow-up

The bottom section intentionally has variable breathing room above its visible
actions. The desktop smoke regression covers delayed Update appearance and a
short expanded sidebar; authenticated visual behavior still needs browser
verification.

## Release notes

Search and Share remain available during account restoration. Profile loading
and account actions no longer shift those controls, and the account menu shows
its artwork item as soon as access resolves. Protected pages and signing controls
show loading during account restoration instead of flashing a logged-out or
access-denied message.
