# PR Report: Browser-Derived Cosmetic Environment Identity

PR: https://github.com/6529-Collections/6529seize-frontend/pull/3542
Branch: `agent-prxt/cosmetic-env-id` -> `main`
Related PRs: None

## Summary

The environment badge and favicon now identify the environment from the URL
actually open in the browser, without changing any functional or server-side
environment behavior.

## What Changed

- Resolves cosmetic environment identity from `window.location.origin` with a
  complete production fallback.
- Keeps the environment badge empty through server rendering and initial
  hydration, then reveals the browser-derived non-production identity.
- Maintains one runtime PNG/SVG favicon pair and restores it after App Router
  metadata updates.
- Keeps route metadata favicon-free so it cannot conflict with the runtime
  controller.
- Covers production, shared staging, personal/named staging, localhost,
  hydration, navigation-time head updates, and malformed or inaccessible
  browser locations.

## Frontend Impact

- Routes/views: All App Router routes inherit the root runtime favicon.
- Components: Environment badge identity and root favicon ownership.
- Generated API/client: Not affected.
- User-visible behavior: Badges and favicons match the browser-visible host.

## Config / Env

- `BASE_ENDPOINT` remains a pre-existing required public runtime value. It
  continues to control API behavior, public-review gates, canonical/share and
  Open Graph URLs, and server metadata titles/descriptions.
- Browser location is used only for the environment badge and favicon. Missing,
  inaccessible, empty, malformed, or unsupported browser locations use the
  complete `https://6529.io` production identity.

## Release Notes

Non-production environment badges and favicons now reflect the host open in the
browser, while functional environment configuration remains unchanged.
