# Per-message reply collapse

[Frontend PR #4778](https://github.com/6529-Collections/6529seize-frontend/pull/4778) · [Backend PR #2422](https://github.com/6529-Collections/6529seize-backend/pull/2422)

## Summary

When wave-wide collapse is off, authors can choose **Collapse replies** from the desktop or mobile actions menu on their top-level chat drops. All existing and future replies to that drop appear in its thread for everyone. Authors can choose **Show replies inline** to reverse it.

## Frontend impact

- Links and in-chat jumps open the top-level thread in both collapse modes and scroll to the exact reply. The top-level message has a subtle tint. The linked reply has a brighter tint and a blue edge. Other replies keep their normal appearance. Older links load directly from the reply’s position in the thread.
- Empty threads update in place when reply placement changes. Populated threads refresh the timeline to move their replies. Individual collapse keeps the wave’s unread and notification rules. Pending sends and live thread counts use the root to keep replies together.
- The web client opts into the mixed timeline and uses the matching generated API types. The backend schema and API must deploy before the web client.

## Risks and follow-ups

The web client can resolve wave-wide reply ancestry against an older API by walking the parent chain. Deploying the companion API enables a single lookup.
