# PR Report: Profile Wallet Labels

PR: https://github.com/6529-Collections/6529seize-frontend/pull/4304
Branch: `agent-prxt/profile-wallet-labels` → `main`

## Summary

Profile pages use the viewed profile’s singular Wallet heading, such as
`prxt0's Wallet`, with a right-aligned `1 of 4 addresses` count based on the
profile’s address list and current settings limit.

## What Changed

- Update the shared desktop, mobile browser and native/mobile profile section,
  preserving identity fallbacks, long-name wrapping and owner/visitor behavior.
- Hide the counter while limits are unknown rather than showing a bare number.
  Previously loaded limits remain usable after a settings refresh failure.
- Preserve address cards, primary labels, Wallet Checker, consolidation actions
  and ID Statements.
- Align message copy, browser expectations, profile/delegation documentation and
  the published Help Bot corpus with the Wallet terminology.

## Release Notes

The Wallet heading intentionally stays singular when a profile has several
addresses. Counts now describe addresses explicitly and use the existing wallet
policy maximum. No backend contract or configuration changes are required.

## Risks / Follow-Ups

Desktop/mobile browser and native-device visual verification remains outstanding;
local development server startup was not authorized for this task.
