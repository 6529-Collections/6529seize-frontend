# One encrypted DM entry per person

Leaving an encrypted chat and starting a replacement used to leave separate entries for the same person. The encrypted list and sidebar now group those histories under one person, while group chats remain separate. The Chat history control opens earlier messages, including imports kept in the earlier chat. Old links retain their original history, and current-chat and continuation actions let the user resume messaging.

The original peer identity survives membership changes without restoring that person to the current roster. Active, unmuted histories contribute unread counts; opening the row prioritizes incoming unread history and previews that same history. Reading it leaves other unseen histories unread; the combined badge intentionally totals those histories, and the history control exposes their individual counts. When no active history remains, the displayed history keeps its own unread and mention counts, respecting its mute setting. Readable old messages retain mute, block, and report actions while replies, reactions, edits, and deletes stay unavailable. A lone participant's remainder is no longer reused as a deliverable DM. The engine syncs invitations before creation, coalesces concurrent starts within that engine, and consistently selects among known active chats.

This is a frontend change using decrypted peer metadata. It does not delete or merge cryptographic groups, rewrite messages, change backups, or require an API migration. Simultaneous starts on separate devices can still create separate groups; once both are known locally, they share an entry and remain accessible. Server-wide pair reservation is a separate protocol decision.

The existing manual encrypted-DM sandbox scenario now covers leaving, continuing, seeing one entry, selecting earlier history, and returning to the current chat on desktop and phone. The full application scenario still needs execution in an authorized app environment; isolated browser rendering does not establish that end-to-end result.

History controls remain a named “Chat history” region even when only one ended session is available. Among usable sessions, the group identifier is the deterministic tie-breaker: local message arrival times must not make devices select different active chats.
