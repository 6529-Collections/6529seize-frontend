# PR Report: E2E startup, navigation, and dependency installation

Related PRs: [startup #4197](https://github.com/6529-Collections/6529seize-frontend/pull/4197), [compact Network filter #4200](https://github.com/6529-Collections/6529seize-frontend/pull/4200)

## Summary

Repair browser-test setup and expectations exposed by the mobile startup and compact Network sheet changes, and recover safely from slow Linux dependency installation in staging and production E2E. Application behavior and staging authentication remain unchanged.

## What Changed

- The fresh phone context inherits fixture storage state before the first navigation, preserving staging access without pre-hydrating the homepage. Its own read-only mutation guard protects that context.
- Search controls are awaited until visible and enabled instead of inspected immediately while navigation is loading.
- Wave-search route checks poll the current URL directly after the dialog is ready. They retain the same selected-wave pathname or local query-wave match without waiting for unrelated images to finish the page load event. Message search, minimum query, empty results, and clearing remain required.
- Tablet and touch Network coverage checks precise bottom alignment and stable height when widening the viewport, preserving the intended compact-sheet behavior rather than demanding a near-full-screen sheet.
- Main Stage app artwork coverage awaits API-backed section readiness and checks settings HTTP status before reading its payload. The leaderboard response is captured alongside the click, preserving tab ordering and artwork-to-response checks.
- Mint-page coverage waits up to twenty seconds for the original artwork image to finish loading with positive intrinsic dimensions, then requires it to be visible. Each attempt attaches the source, completion state, and intrinsic/rendered dimensions to distinguish gateway loading failures from collapsed layout.
- Existing specs remain in their current packs; no exclusions or extra retries were added.
- Staging and production E2E allow ten minutes for Playwright system dependency installation. The existing retry first waits up to five minutes for apt/dpkg locks to clear, then installs within its fifteen-minute step budget. Locks are never deleted and package-manager processes are never killed. The final setup check still fails unless an installation succeeds.

## Risks / Follow-Ups

The targeted browser scenarios were exercised against staging; a complete pack run remains the broader execution check. The Network assertion deliberately supports both main's taller sheet and #4200's compact sheet while rejecting desktop centering at tablet/touch widths.

The later Main Stage app failure contained repeated HTTP 429 errors while navigation remained in its loading state. [#4153](https://github.com/6529-Collections/6529seize-frontend/pull/4153) increases API request volume through per-rendered-drop competition lookups. Runtime request pacing and background pausing belong to [#4178](https://github.com/6529-Collections/6529seize-frontend/pull/4178); this PR retains HTTP failure assertions and changes no application runtime code.

The dependency installation change addresses [a setup failure](https://github.com/6529-Collections/6529seize-frontend/actions/runs/37794245246) where downloads exceeded the former three-minute step timeout and the retry collided with the surviving apt-get process. Persistent installation failures remain fatal; this does not fix staging HTTP 500 or 429 responses. E2E workflows are dispatched from main, so their updated setup logic takes effect after this PR is merged there.

The mint-image readiness change addresses [a production failure](https://github.com/6529-Collections/6529seize-frontend/actions/runs/37800355466) where card #558's original gateway image remained hidden during the former five-second visibility check on all three attempts. The same artwork subsequently rendered on live production. The saved failure evidence does not establish its exact loading duration; the bounded wait retains failures for broken images and hidden layout rather than guaranteeing gateway availability.

The wave-search URL change addresses [a later production failure](https://github.com/6529-Collections/6529seize-frontend/actions/runs/37806223221) where all three attempts reached the expected wave and opened its search dialog, but the predicate-based URL matcher also waited for page load. Route identity is now checked independently of external resource loading, with the original timeout and route conditions preserved.
