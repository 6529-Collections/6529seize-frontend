# PR Report: Staging E2E readiness and competition request bursts

PR: https://github.com/6529-Collections/6529seize-frontend/pull/4201
Branch: agent-prxt/staging-e2e-startup-fixes -> main
Related PRs: [startup #4197](https://github.com/6529-Collections/6529seize-frontend/pull/4197), [compact Network filter #4200](https://github.com/6529-Collections/6529seize-frontend/pull/4200)

## Summary

Repair browser-test setup and expectations exposed by the mobile startup and compact Network sheet changes, and pace competition-context lookups that can overwhelm the API while loading chat. Staging authentication and competition authorization remain unchanged.

## What Changed

- The fresh phone context inherits fixture storage state before the first navigation, preserving staging access without pre-hydrating the homepage. Its own read-only mutation guard protects that context.
- Search controls are awaited until visible and enabled instead of inspected immediately while navigation is loading.
- Tablet and touch Network coverage checks precise bottom alignment and stable height when widening the viewport, preserving the intended compact-sheet behavior rather than demanding a near-full-screen sheet.
- Competition-context lookups share a queue with a 250 ms start interval and at most two concurrent requests. Aborted queued lookups never reach the API; dispatched requests retain their original cancellation signal, structured errors and parent checks.
- Main Stage app artwork coverage waits for API-backed section readiness, checks settings HTTP status before reading its payload, and captures the leaderboard response alongside the click. Its tab order and artwork checks remain intact.
- Existing specs remain in their current packs; no exclusions or extra retries were added.

## Risks / Follow-Ups

Context decorations can arrive progressively on large drop lists instead of starting all lookups together. The queue reduces this request source's burst and sustained rate; it cannot guarantee that other clients sharing an IP will not exhaust the API quota. Application pacing still needs execution in an environment containing the updated frontend; existing staging exercises the revised browser test, not the un-deployed runtime change. A complete pack run remains the broader execution check. The Network assertion supports both main's taller sheet and #4200's compact sheet while rejecting desktop centering at tablet/touch widths.
