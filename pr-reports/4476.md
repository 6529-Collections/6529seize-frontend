# PR Report: Shared staging deployment queue

PR: [#4476](https://github.com/6529-Collections/6529seize-frontend/pull/4476)
Branch: `agent-prxt/fix-staging-deploy-queue` -> `main`

## Summary

An active frontend staging run can finish its verified pinned artifact while a
newer staging push waits. A newer branch head alone no longer invalidates the
active deployment.

## What Changed

- Require the candidate to remain in fetched staging history and prepare its
  exact SHA in a temporary detached worktree, including its deployment helper.
  Leave the live checkout and legacy restart files unchanged on both success
  and rejection, and remove the temporary source worktree after the attempt.
- Fetch complete history from shallow managed checkouts before checking source
  and runtime ancestry, so truncated history cannot reject a valid advance.
- Under the existing instance deployment lock, verify the pinned checkout and
  require the healthy running app's SHA to be an ancestor of, or equal to, the
  candidate. Reject older, divergent, or unverifiable reruns before activation.
- Preserve `cancel-in-progress: false`, workflow serialization, the default
  single pending slot, artifact integrity checks, exact runtime-version checks,
  idempotency, and automatic rollback.

## Release Notes

Queued shared-staging updates no longer cause an otherwise valid active
deployment to fail merely because the branch advanced. Additional pushes may
still replace the pending run with the latest cumulative integration. Intentional
rollback uses a new reviewed revert commit.

  confirmed B remained live. The normal failed-deployment alert was expected.

## Risks / Follow-Ups

- Already-created runs retain their original workflow behavior. The new policy
  applies to runs containing this change.
- Missing ancestry or an unhealthy running version blocks activation safely.
- The live A/B queue and old-A replay checks exercised the original queue fix.
  The subsequent shallow-checkout and isolated-source handling is covered with
  real Git repositories, shallow clones, failed fetches, and managed/legacy
  runtime rejection and forward-deployment cases; it has not been redeployed.
- Broader unchanged Museum workflow shell cases could not complete locally:
  Bash 3.2 lacks their required `mapfile` builtin.
