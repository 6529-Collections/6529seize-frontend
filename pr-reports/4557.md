# PR Report: Desktop downloads and macOS 12 recovery

PR: https://github.com/6529-Collections/6529seize-frontend/pull/4557
Branch: agent-prxt/desktop-download-compatibility → main
Related Core PR: https://github.com/6529-Collections/6529-core/pull/281

## Summary

The Apps page provides direct installers in operating-system accordions, with
full-width Mobile and Desktop sections and compact white Download buttons.

## What Changed

- Windows offers x64 and ARM64 EXEs; Linux offers AppImage, DEB and RPM packages.
- macOS separates the current release from the last Monterey-compatible release,
  with Apple silicon/Intel options and instructions for recovering an app that
  stopped opening after an incompatible update. Existing application data stays.
- Version numbers and installer paths come from independent release manifests.
  New releases appear without changing frontend release constants.
- Optional Arweave mirrors come from versioned catalogs maintained by Core.
  Missing mirror metadata does not hide the primary download.
- Partial release failures remain visible and retryable. Unsafe filenames,
  mismatched versions and untrusted mirror URLs are not exposed as links.
- The help corpus and Apps-page documentation describe the new download flow.

## Compatibility

The current Mac updater feed uses a Darwin minimum corresponding to macOS 13+.
The separate `latest-macos-12.yml` download feed currently advertises 0.3.15;
normal Core publication preserves it. This is a download source, not a new
auto-update channel. The live manifests and initial mirror catalogs are already
available independently of these code changes.

New Core manifests also supply `minimumMacOSVersion` for display, independently
of the updater's Darwin requirement. Older feeds use a verified mapping, including
the macOS 15 → 26 naming jump. Unknown Darwin requirements without explicit
display metadata fail visibly rather than being mislabeled. Native accordion
grouping degrades to multiple open sections in older browsers; downloads remain
accessible.

## Risks / Follow-Ups

Full Next route browser testing still needs an authorized application build or
deployed environment. New source copy falls back to English in untranslated
locales, consistent with the page's existing locale policy. The Electron patch
in the Core PR ships only when a future Desktop release is built.
