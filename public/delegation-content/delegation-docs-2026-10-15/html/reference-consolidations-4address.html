Consolidations are distinct from delegations. They are on-chain records that let 6529 treat up to four addresses you control as one for calculating wallet-related metrics such as total cards held, total unique cards held, and TDH.

A consolidation of four addresses needs every pair of addresses linked in both directions: six pairs and twelve registrations. Each registration is a consolidation (use case 999) on "Any Collection" or "The Memes", and either collection works for each direction. Consolidations do not expire.

A fourth address counts only for links registered on or after 15 October 2026 00:00 UTC. A group of four counts when one of its addresses has all three of its links registered in both directions on or after that time, which is normally the address you add as the fourth. Register those links only after that time. Before then, a consolidation counts at most three addresses.

Assuming four sample addresses:

  • Address A (vault)
  • Address B (second vault, for example a Safe)
  • Address C (transaction wallet)
  • Address D (minting wallet)

The Six Links

Every pair in a four-address consolidation registers both directions.
Pair First direction Second direction
A ↔ B A registers B B registers A
A ↔ C A registers C C registers A
A ↔ D A registers D D registers A
B ↔ C B registers C C registers B
B ↔ D B registers D D registers B
C ↔ D C registers D D registers C

Add a Fourth Address to an Existing Group

If Addresses A, B and C are already consolidated, add Address D with four transactions:

  1. Using Address A, register a consolidation with Address D: navigate to the Delegation Center Section, click 'Register Consolidation,' choose the collection, enter wallet Address D, and execute the transaction.
  2. Using Address B, register a consolidation with Address D.
  3. Using Address C, register a consolidation with Address D.
  4. Using Address D, register consolidations with Addresses A, B and C in one batch transaction, as described below. Address D signs last.

Steps 1 to 3 can happen in any order and at any time, and nothing changes until Address D signs. When Address D's batch confirms, the group becomes four addresses in one step.

Do not let the new address sign first. If it signs before the existing members, the group splits temporarily while the remaining links arrive. Each split re-runs the profile split and merge, and TDH-wave votes above the temporarily lower TDH are reduced and are not restored.

Create a New Group of Four

If none of the addresses is consolidated yet, each address sends one batch transaction to the other three, in any order. The group only grows.

If Addresses A and B are already consolidated and Addresses C and D are new, the existing members go first: A sends one batch to C and D, B sends one batch to C and D, and then C and D send theirs, in either order.

Register Several Links in One Transaction

The NFTDelegation contract (0x2202CB9c00487e7e8EF21e6d8E914B32e709f43d on Ethereum mainnet) has a batchDelegations function that registers up to five links in one transaction. For example, to register Address D's links to Addresses A, B and C, call batchDelegations from Address D with one entry per link in each list, in the same order:

batchDelegations values for consolidation links
Parameter Value for each link
_collectionAddresses 0x8888888888888888888888888888888888888888 (Any Collection)
_delegationAddresses The address to link with (Address A, Address B, Address C)
_expiryDates 64060588800 (no expiry)
_useCases 999 (Consolidation)
_allTokens true
_tokenIds 0

You can send this call from any tool that can call contract functions, such as the Safe Transaction Builder described in How to Delegate using SAFE (formerly GNOSIS)? To register a single link, use the Register Consolidation form.

With a Delegation Manager

A delegation manager (use case 998 on Any Collection) can register and revoke consolidations for the address that appointed it. There is no batch for managers, so a manager sends one transaction per link. Keep the same order: links from the existing members first, links from the new address last.

Remove an Address

  • If the address still has its key, it sends one batchRevocations transaction to all the other addresses. For each link, use the collection the link was registered on, the address to unlink and use case 999. The links are revoked together, in one step.
  • If its key is lost or compromised, every remaining address revokes its link to it, one transaction each. Send them back to back: the removed address keeps access to the profile until the last revocation lands.
  • To replace an address without ever dropping below three, add the new address as the fourth first, then remove the old one. See Use Case 4 in Consolidation Use Cases.

Notes

  • When links conflict, the newest confirmed link wins. If an address in your group completes a link in both directions with a new address, that link moves it out of the group.
  • Every address in a consolidation is a full key to the profile: it can sign in as the profile, set the primary address and redirect airdrops. When a group forms, the profiles of its addresses merge and the merge cannot be undone. Consolidations are for one person's addresses, not for multiple individuals.
  • In the Delegation Center Section, click 'View/Manage' in the collection you used and check the consolidation status in the Consolidations area.
  • Within the context of The Memes, the purpose of consolidation is to allow you to consolidate any addresses that you own.
