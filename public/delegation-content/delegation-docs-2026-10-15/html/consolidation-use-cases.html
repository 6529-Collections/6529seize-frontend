Overview

Consolidation is a process to recognize that most NFT users use multiple addresses for their NFTs. In fact, it is generally a good practice to separate "vault", "transaction" and "minting" addresses. Please see an example architecture of this type here.

For the purposes of The Memes, we recognize up to 4 addresses as being treated as one, for the purpose of calculating community metrics such as total cards, unique cards, TDH and other metrics.

Every pair of addresses in a consolidation needs to register a "consolidation" (use case 999) with each other, in both directions. Two addresses need 2 registrations, three addresses need 6 and four addresses need 12. Each direction can be registered on "Any Collection" or "The Memes". Consolidation registrations do not expire. Details for how to sign these transactions are in this Consolidation FAQ.

The purpose and spirit of this approach is to support NFT collectors in following safe wallet practices. It is not to support multiple individuals consolidating their TDH. We reserve the right to change the algorithm in the future, eliminate it altogether, apply manual overrides (if we think it is abused) or not apply overrides (even if it is abused).

These are analytic metrics, not protocol functions, so the goal is to be roughly right (say 80%) as with all other approaches of this type and should be understood in this spirit. There will always be edge cases that fall outside of the parameters of our approach and that is OK.

The Fourth Address

A fourth address counts only for links registered on or after 15 October 2026 00:00 UTC. A group of four counts when one of its addresses has all three of its links registered in both directions on or after that time. In practice, that is the address you add as the fourth, so register its links only after that time. Before then, a group counts at most three addresses. Groups of two or three addresses work as before, and their existing registrations stay valid.

When Links Conflict

6529 builds groups from confirmed links, newest first, so the newest link wins. If an address in a group completes a link in both directions with a new address, that newer link moves it out of its current group. This is how you leave a group or pair an address with a different one.

One Transaction per Address

The NFTDelegation contract's batchDelegations function registers up to five links in one transaction, so each address can register all of its links at once. The order of those transactions matters:

  • Adding Address D to an existing group of Addresses A, B and C: A, B and C each register one link to D first, in any order and at any time. Nothing changes yet. D signs last, with one batch to A, B and C, and the group becomes four addresses in one step.
  • Creating a new group of four: each address sends one batch to the other three, in any order. The group only grows.
  • Adding Addresses C and D to an existing pair of Addresses A and B: the existing members go first (A sends one batch to C and D, B sends one batch to C and D), then C and D sign, in either order.
  • A delegation manager (use case 998 on Any Collection) can register and revoke consolidations for the address that appointed it. There is no batch for managers, so a manager sends one transaction per link.

Why the Order Matters

If the new address signs before the existing members, the group splits temporarily while the remaining links arrive. Each split re-runs the profile split and merge, and TDH-wave votes above the temporarily lower TDH are reduced and are not restored. Signing with the existing members first and the new address last avoids this.

Removing an Address

  • If the address still has its key, it sends one batchRevocations transaction that revokes its links to all the other addresses at once.
  • If its key is lost or compromised, every remaining address revokes its link to it, one transaction each. Send them back to back: the removed address keeps access to the profile until the last revocation lands.

What Joining a Consolidation Means

  • Every address in a consolidation is a full key to the profile: it can sign in as the profile, set the primary address (use case 997) and redirect airdrops (use case 3). Only consolidate addresses that you control.
  • When a group forms, the profiles of its addresses merge, and the merge cannot be undone. The handle and profile picture that remain come from the member profile with the highest CIC, then the highest TDH.
  • Holdings across the consolidated addresses combine for TDH boosts such as full sets, seasons, Genesis/Nakamoto and Gradients. Transfers between addresses in the confirmed consolidation keep their acquisition time.
  • TDH updates within minutes of a change and fully at the next 00:00 UTC snapshot.

Use Case 1

Scenario

  • I have 2 addresses (for example: vault and transaction)
  • I move my cards between the 2 addresses for various reasons
  • At any point in time any card can be in any of the 2 addresses

Solution

  • Consolidate
    • Address A ↔ Address B
  • At all points in time, total cards, unique cards, TDH and other future metrics are treated as if both addresses were consolidated into one address

Use Case 2

Scenario

  • I have 3 addresses (for example: vault, transaction and mint)
  • I move my cards between the 3 addresses for various reasons
  • At any point in time any card can be in any of the 3 addresses

Solution

  • Consolidate
    • Address A ↔ Address B
    • Address B ↔ Address C
    • Address C ↔ Address A
  • At all points in time, total cards, unique cards, TDH and other future metrics are treated as if all three addresses were consolidated into one address

Use Case 3

Scenario

  • I used to have my cards in my hot address (Address A)
  • I moved all my cards to my vault address (Address B)
  • I am now minting cards from my new hot address (Address C) and tranferring them to Address B some days later

Solution

  • Consolidate
    • Address A ↔ Address B
    • Address B ↔ Address C
    • Address C ↔ Address A
  • At all points in time, total cards, unique cards, TDH and other future metrics are treated as if all three addresses were consolidated into one address

Use Case 4

Scenario

  • My 3 addresses are consolidated: vault (Address A), transaction (Address B) and minting (Address C)
  • I want to replace Address C with a new address (Address D), for example a new hot wallet
  • I want my addresses to keep counting as one throughout

Step 1: Add the New Address

  • Consolidate
    • Address A ↔ Address D
    • Address B ↔ Address D
    • Address C ↔ Address D
  • A, B and C each register their link to D first. D signs last, with one batch to A, B and C, and the group becomes four addresses in one step. Register these links on or after 15 October 2026 00:00 UTC so that the fourth address counts.

Step 2: Remove the Old Address

  • Revoke
    • Address C → Address A, Address B, Address D
  • C sends one batch revocation to A, B and D. The group goes from four addresses to three in one step and never drops below three, so total cards, unique cards, TDH and other metrics keep treating the remaining addresses as one.
  • If someone else may control Address C, remove it first instead of waiting to add D: while C is in the group, it is a full key to your profile. If C's key is lost, A, B and D each revoke their link to C, back to back.

Use Case 5

Scenario

  • I have 4 addresses (for example: vault, a second vault such as a Safe, transaction and mint)
  • I move my cards between the 4 addresses for various reasons
  • At any point in time any card can be in any of the 4 addresses

Solution

  • Consolidate
    • Address A ↔ Address B
    • Address A ↔ Address C
    • Address A ↔ Address D
    • Address B ↔ Address C
    • Address B ↔ Address D
    • Address C ↔ Address D
  • With the fourth address's links registered on or after 15 October 2026 00:00 UTC, total cards, unique cards, TDH and other future metrics are treated as if all four addresses were consolidated into one address. See How to Register Consolidations (4 Addresses)?
