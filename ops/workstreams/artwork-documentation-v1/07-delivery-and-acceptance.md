## 2. Contract fixtures to produce in AD-01

Use fictitious artists/people, synthetic consent documents and permitted test artwork. Do not put real private pilot evidence in repository fixtures.

Required fixture cases: empty draft; partially answered photography record; truthful unknown/unavailable answers; ordinary photograph ready for confirmation; composite with missing ingredients; restricted consent; long original statement plus short caption; shared artist-record update; historical confirmed revision with newer draft; changed profile version; file processing/failure/unsupported preview; source-link failure; unauthorized redaction; localized/RTL record.

Each fixture includes request headers/body where relevant, status code, projected response, context/artist-record version and expected UI status. Make the backend contract tests own serialization and policy results. FE tests should assert behavior at the interaction boundary rather than copying backend validators line for line. Canonicalization fixtures include Unicode NFC/LF preprocessing, unchanged array order, stable key serialization and a known SHA-256 digest of the actual serialized bytes.

## 4. Rollout and operational ownership

Use backend capability/config flags for domain access, pilot program enablement and inline-entry enablement. The frontend renders only allowed surfaces, but a flag is never authorization. Default public self-service off for pilot; allow selected profiles and assigned coordinators/reviewers. The initial feature can onboard the selected works through standalone links before enabling ongoing self-service discovery.

Before onboarding: appoint a product owner, backend/storage owner, frontend owner, program coordinator and named lane reviewers through existing authority. Do not hardcode a person from a public Wave into a role. Record deployed API/schema/FE versions and the resolved profile hash in pilot evidence. Confirm private bucket/access configuration, job processing, capacity defaults, backup ownership and a tested restore path.

Try the complete experience with two invited artists representing a straightforward image and a more complex process or file set. Check whether copy makes the purpose clear, whether they understand public-intent versus present privacy, and where they stop. Then extend to the full roster. Invitations/communications are separate authorized operations; neither this spec nor an import sends them automatically.

Record findings as concrete usability or implementation defects. Measure starts, saved returns, time spent by section in aggregate, confirmation/review progress and save/upload failure counts. Exclude text, filenames, sensitive rights categories and original URLs from analytics. Report optional-interview uptake separately from required readiness.

Rollback hides entry points and disables new mutations through the server while leaving authorized read access available when safe. It does not drop tables, delete uploads, rewrite confirmed records or detach source drops. Use additive migrations and keep old schema readers until rollback is no longer needed. If read access itself is implicated in a bug, close that surface explicitly and preserve data for repair.

## 5. Definition of done and deferred work

The feature is done when artists can start during submission or afterward, resume server-saved modular drafts, supply byte-preserved originals, understand why each section matters, confirm a version and resolve permissioned feedback; coordinators can inspect the same version and track honest lane outcomes. Required integration, isolation, concurrency, upload and UI checks must have real passing evidence.

Do not substitute a polished mockup for working persistence, a schema for a private upload path, a checkbox for inspected consent, or a screenshot for tested authorization. Conversely, do not hold this intake delivery for Stream contract deployment or a permanent-storage publisher.

Explicit later backlog: mint preparation; final release-package composition; IPFS/Arweave upload/pinning/funding; public documentation publication; Stream typed signatures and canonical schema admission; collection/token topology; token allocation; payment configuration; artist authority onboarding; wallet succession; Museum accession transactions; contract metadata updates; public authenticity badges; multiple-author threshold approval; real-time coediting; automatic translation/transcription; full offline editing. Later work consumes this domain through the [handoff boundary](08-stream-handoff-boundary.md).
